# 사이드 패널 화면·테마 설계와 검증

## 화면 구조

긴 대화와 실행 설정·세션 목록·작업 기록이 한 문서에서 함께 늘어나던 구성을 바꿨다. 패널 전체는 창 높이에 맞추고, 사용자 목적에 따라 **대화**, **세션**, **브라우저**를 구분한다.

| 영역 | 배치·동작 |
|---|---|
| 고정 헤더 | Bridge 연결 상태, 설정, 현재 브라우저 작업 중단. 모든 보기에서 접근 가능 |
| 대화 | 메시지 영역만 독립 스크롤. 입력란은 아래에 유지하고 기존 메시지를 읽는 동안 강제로 아래로 이동하지 않음 |
| 실행 설정 | 환경·작업 디렉터리·모델·에이전트·variant를 별도 화면에서 조정 |
| 작업 도구 | 사용량·압축·할 일·하위 작업·파일 변경·셸·커맨드·스킬·MCP를 필요할 때 열기 |
| 세션 | 상위 세션 목록·검색·관리. 하위 세션은 접힌 목록에서 필요할 때 조회 |
| 브라우저 | 브라우저 선택·작업 탭·타임라인을 대화와 분리해 확인 |
| 테마 | 작은 색상 미리보기와 선택 목록. 설정 페이지와 저장값을 공유 |

대화 컴포넌트와 서버 연결은 보기를 바꿔도 유지한다. 따라서 보기 전환은 대화 중단이나 미전송 초안 삭제를 의미하지 않는다. 각 설정 화면은 **대화로 돌아가기**와 Esc를 제공하고, 닫을 때 열었던 버튼으로 키보드 초점을 돌린다. 탭은 좌우 화살표·Home·End를 지원한다.

## 대화 영역

- **응답 단위**: OpenCode는 한 응답을 단계별 assistant 메시지 여러 개로 저장한다. 화면에서는 사용자 메시지 하나와 그에 이어지는 assistant 메시지들을 각각 하나의 응답 단위(turn)로 묶는다. 머리글(에이전트 이름·시각)은 응답마다 한 번만 표시한다.
- **구분**: 사용자 메시지는 오른쪽 정렬 말풍선이며 배경은 `--bubble` 토큰이다. `--bubble`은 base를 테마 blue 쪽으로 섞은 색이다. 응답은 전체 폭으로 표시한다. 새 사용자 메시지 앞에 구분선을 둔다. `--bubble`도 대비 검사의 배경 목록에 포함한다.
- **빈 부분 숨김**: 공백뿐인 텍스트·추론, step 표시, snapshot은 렌더링하지 않는다. 볼 내용이 없는 응답 단위도 표시하지 않는다. 응답을 기다리는 동안에는 "응답을 준비하는 중…"을 표시한다.
- **메시지 작업**: 분기·되돌리기는 사용자 메시지에만, 복사는 텍스트가 있는 응답 단위에만 둔다. 평소에는 투명하고, 마우스를 올리거나 초점이 있을 때 나타난다. 터치 기기(`hover: none`)에서는 항상 보인다. 공간을 유지하므로 나타날 때 본문이 움직이지 않는다.
- **도구 카드**: 접힌 상태에서도 제목 아래에 주요 입력(URL·ref·텍스트·명령 등) 한 줄을 보여 준다. 간격은 연속 호출을 고려해 촘촘하게 둔다.
- **렌더링 비용**: 메시지 카드는 `memo`이고 처리기는 안정된 참조다. reducer는 HTTP 재조회 결과에서 내용이 같은 메시지의 객체를 재사용한다. 따라서 입력하거나 응답을 재조회해도 바뀐 메시지만 다시 그린다.

## 세션 관리

- 하위 세션 화살표는 하위 세션이 있는 행에만 둔다. v1 Session에는 하위 개수가 없으므로 다음과 같이 확인한다.
  - 화면에 보이는 행(루트와 펼친 행의 자식)만 `/session/:id/children`으로 확인한다. 동시 요청은 4개로 제한한다.
  - 결과는 연결 단위로 캐시한다. `session.created`/`session.deleted` 이벤트로 캐시를 갱신한다.
  - 확인 전에는 화살표 대신 같은 폭의 빈칸을 둔다. 따라서 행이 밀리지 않는다.
- 이름 변경·전체 분기·내보내기·삭제는 행과 대화 제목의 **⋯** 메뉴에 둔다. 이름 변경은 해당 위치의 인라인 입력이다(Enter 저장, Esc 취소, IME 조합 보호, 낙관적 반영 후 실패 시 복원). 삭제는 메뉴 안에서 한 번 더 확인한다.
- 삭제 후에는 실행 환경을 다시 연결하지 않는다. 목록·캐시·메시지에서 해당 세션만 제거하고, 목록을 비우지 않은 채 다시 조회한다. 선택된 세션이나 그 상위 세션을 지우면 선택을 해제한다.
- `session.updated`/`todo.updated`는 이벤트에 담긴 새 상태를 바로 적용한다. 대화 전체·todo·diff·세션 목록을 다시 받지 않는다. 새 루트 세션만 목록을 다시 조회한다.

## 세션과 응답 상태

상위 목록은 v1 `GET /session?roots=true&limit=50`으로 조회한다(하위 세션 화살표·관리 메뉴는 위의 **세션 관리** 절). **더 보기**는 요청 범위를 50개씩 늘리고, 새 검색은 50개부터 시작한다. 설치본 v1의 `start`는 갱신 시각의 하한 필터이므로 이전 페이지 커서로 사용하지 않는다. 하위 세션을 전체 목록에서 뒤늦게 제거하는 방식으로 조회 한도를 소모하지 않는다.

하위 세션은 부모별 `/children` 요청으로 펼칠 때 불러온다. 다시 펼치면 새로 조회하고 중복 진행 요청은 억제한다. 선택한 세션의 정보는 상위 목록과 별도로 보관해 하위 대화 제목·모델·부모 이동이 유지된다. 실행 환경이 바뀌면 이전 조회 결과를 버린다.

응답 스트림의 정상 연결만으로 모든 완료 이벤트를 받았다고 가정하지 않는다. 선택한 세션이 busy/retry이면 약 2초 간격으로 상태·메시지·대기 요청을 재조회한다. 단, 직전 1.5초 안에 그 세션의 메시지 이벤트가 도착했다면 스트림이 정상 전달 중이므로 이번 조회를 건너뛴다. 전송 성공 뒤에는 초기 이벤트가 없더라도 15초 동안 관찰하고, 화면·창으로 돌아올 때도 재조회한다. 진행 중인 재조회는 겹치지 않으며 숨긴 문서에서는 주기적 네트워크 조회를 건너뛴다. busy/retry가 해제되고 전송 관찰창이 끝나면 주기적 조회를 멈추며, 환경 전환·패널 종료 때도 정리한다. 이 경로는 무거운 diff·하위 목록을 반복해서 가져오지 않는다.

별도로, todo·children·diff의 응답 대기가 메시지와 SSE 반영을 막지 않도록 분리했다. `session.updated`가 메시지 이벤트로 오인되어 빈 assistant 카드가 생기던 문제도 이벤트 종류를 명시적으로 구분해 수정했다. 누락 복구와 합성 회귀의 성공을 실제 사용자가 겪은 모든 지연의 원인 확인이나 실제 모델 작업 성공으로 해석하지 않는다.

## 팔레트와 라이선스

Catppuccin의 Latte, Frappé, Macchiato, Mocha를 사용한다. **시스템 설정**은 밝은 모드에서 Latte, 어두운 모드에서 Mocha로 연결한다. 이전 `light`·`dark` 저장값은 각각 Latte·Mocha로 옮긴다.

팔레트 원본은 공식 `catppuccin/palette`의 v1.8.0, 커밋 `07d02aa110ef9eb7e7427afca5c73ba9cf7f8ebd`에 고정했다. 원본 JSON은 `extension/src/theme/catppuccin-palette.json`, MIT 라이선스는 `scripts/licenses/catppuccin-palette-1.8.0-LICENSE`에 보관하고 배포의 제3자 고지에 포함한다. 런타임 CDN이나 추가 npm 패키지를 사용하지 않는다. [공식 고정 커밋](https://github.com/catppuccin/palette/tree/07d02aa110ef9eb7e7427afca5c73ba9cf7f8ebd)

색상 이름을 CSS 곳곳에 직접 넣지 않고 본문·보조문·표면·강조·오류·포커스·입력 경계에 쓰는 토큰으로 변환한다. 공식 팔레트의 모든 원색 조합이 작은 글자에 충분한 대비를 제공하는 것은 아니다. 예를 들어 Latte의 원본 blue/base는 약 4.34:1이다. 실제 사용하는 배경들에서 기준에 못 미치는 강조·보조 색은 해당 팔레트의 본문색 방향으로 조정한다. 버튼 위 글자도 최종 배경과 별도로 검증한다.

## 대비·레이아웃 검증 범위

텍스트 대비는 최종 RGB를 선형화해 상대 휘도를 구하고 `(밝은 휘도 + 0.05) / (어두운 휘도 + 0.05)`로 계산한다. 본문·보조문·링크·오류·활성 버튼·placeholder는 4.5:1 이상을 검사한다. 입력 경계와 키보드 포커스는 인접 배경과 3:1 이상인지 확인한다. 반올림 전 수치로 비교한다. [W3C 텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 비텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

단위 테스트는 네 테마의 실제 토큰 조합을 검사한다. 브라우저 테스트는 `getComputedStyle`로 화면에 적용된 글자·배경·placeholder·경계·outline 색을 읽고, 활성 전송 버튼의 hover 상태도 검사한다. 비활성 컨트롤과 장식용 요소는 이 텍스트 대비 검사에서 제외한다. 키보드 이동·초점 복귀·문서 넘침·대화 스크롤·입력란 위치는 별도 동작 검사로 확인한다.

| 테마 | 320×900 | 400×900 | 600×900 |
|---|---|---|---|
| Latte | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 |
| Frappé | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 |
| Macchiato | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 |
| Mocha | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 | 렌더링·대비·스크롤 |

`tests/e2e/workbench.spec.ts`의 W07이 이 12개 조합을 실행한다. W08은 시스템 밝기 변경·선택 저장·Options 동기화, W09는 보기 복귀와 읽던 위치 유지, W10/W12는 연결이 살아 있는 상태에서 빠진 응답 이벤트 복구, W11은 105개 하위 세션을 만든 뒤 상위 목록·중첩 펼치기·하위 세션이 없는 행의 화살표 부재·부모 복귀를 검사한다. W13은 세션 삭제가 해당 행만 제거하고 실행 환경을 다시 연결하지 않음을 검사한다. W06은 메뉴 기반 이름 변경·내보내기와 hover 시에만 나타나는 메시지 작업을 검사한다. 합성 HTTP/SSE 서버만 사용하고 실제 LLM은 호출하지 않는다.

2026-10-11 실행 결과: Linux Chromium의 작업 UI 12개 사례가 통과했고, 초기 세션 생성 재조회의 영향을 제외하도록 강화한 누락 복구 2개 사례도 다시 통과했다. 네이티브 Windows Node v24.18.1과 설치된 Chrome 154.0.8037.99, Windows Bridge exe의 전체 47개 사례가 통과했다. Windows 실행은 격리된 Chrome 프로필의 headless 모드이며, 기존 사용자의 대화·페이지를 fixture로 쓰지 않았다.

Windows의 12개 렌더링 조합에서 텍스트 대비 실패는 0건이었다. 측정한 최솟값은 입력 경계 3.54:1, 포커스 4.79:1, placeholder 5.53:1이며 모두 반올림 전 기준을 통과했다. 높이 900px에서 메시지 표시 영역은 최소 472px였다. 대표 Windows 스크린샷의 Latte 320px·Mocha 600px, 테마 선택·중첩 세션·Options 400px 화면도 직접 확인했다.

결과물은 개발 검증 폴더에만 생성한다.

- Linux: `tests/e2e/.artifacts/workbench-W07-*/theme-<theme>-<width>.png`
- 같은 W07 폴더의 `runtime.json`, `rendered-layout-contrast.json`: 실제 실행 환경과 계산 결과.
- W08 폴더의 `options-macchiato-400.png`, `theme-picker-400.png`와 W11의 `nested-sessions-400.png`.
- Windows: 개발용 검증 복사본의 `tests\e2e\.artifacts`에 동일한 구조로 생성. 이번 UI 검증은 `%LOCALAPPDATA%\AgentBrowser-dev\testing-ui`를 사용했다.

이 파일들은 Git에서 제외된 합성 검증 산출물이며 배포 ZIP에 화면 이미지나 실제 대화 데이터를 넣지 않는다. 화면 크기와 색상·키보드·스크롤의 명시한 사례를 검증한 것이며, 전체 WCAG 적합성 인증이나 모든 OS 접근성 설정·보조 기술·사내 환경 검증을 주장하지 않는다.

# AgentBrowser 문제 해결

## WSL 시작·중지·삭제가 모두 실패할 때

설치 폴더에서 **diagnose.cmd**를 두 번 클릭합니다. 업데이트도 막혀 있으면 새 ZIP을 별도 폴더에 풀고 그 안의 **diagnose.cmd**를 실행한 뒤 기존 설치 폴더를 선택합니다. 설치 파일을 교체하거나 WSL 전체를 종료할 필요가 없습니다. 결과는 기존 설치의 `data/diagnostic-report.json`에 저장됩니다. 보고서는 프로필 이름·경로·토큰·비밀번호·설정 원문을 제외하고 검사 번호와 오류 코드를 남깁니다.

| 코드 | 확인할 항목 |
|---|---|
| `WSL_START_PENDING` | 시작 소유 기록이 아직 확정되지 않았습니다. 반복 시작보다 현재 실행의 상태를 먼저 확인합니다. |
| `WSL_PROBE_TIMEOUT` | 지정 배포판의 상태 확인이 제한시간 내에 끝나지 않았습니다. 실행 중인지 여부는 확정하지 않습니다. |
| `WSL_LAUNCH_UNAVAILABLE`, `WSL_CONTROL_FAILED` | Windows에서 지정 배포판·사용자로 명령을 실행하지 못했습니다. 배포판·사용자 설정을 확인합니다. |
| `WSL_OWNER_FILE_MISSING`, `WSL_OWNER_FILE_UNREADABLE`, `WSL_DATA_ACCESS_DENIED` | 선택한 WSL 사용자에게 설치 데이터의 Windows 마운트 경로가 보이고 읽기·쓰기가 가능한지 확인합니다. |
| `WSL_OWNER_RECORD_INVALID`, `WSL_OWNER_NONCE_MISMATCH` | 실행 소유 기록을 확인할 수 없습니다. `runtime.json`이나 소유 기록을 임의 삭제하지 않습니다. |
| `WSL_DIRECTORY_UNAVAILABLE`, `WSL_EXECUTABLE_UNAVAILABLE` | 프로필의 Linux 작업 폴더·OpenCode 절대 경로와 실행 권한을 확인합니다. |
| `WSL_WINDOWS_EXECUTION_FAILED` | 선택 배포판·사용자에서 Windows Bridge의 짧은 버전 실행을 확인하지 못했습니다. 실행 파일 접근·Windows 실행 허용 여부를 확인합니다. 실패만으로 특정 시스템 설정을 원인으로 단정하지 않습니다. |
| `WSL_INTEROP_REGISTRATION_UNAVAILABLE` (v0.1.8) | 정적 등록 정보 검사 결과입니다. 실제 Windows exe 실행 불가를 증명하지 않으며 오탐 가능성이 있어 v0.1.9에서 실제 실행 검사로 대체했습니다. 이 코드만으로 시스템 설정을 변경하지 않습니다. |
| `WSL_REQUIRED_TOOL_MISSING`, `WSL_PROC_ACCESS_DENIED` | 배포판의 기본 프로세스 도구 또는 `/proc` 접근이 불가능합니다. |
| `WSL_KEEPER_UNVERIFIED`, `WSL_PROCESS_OR_KEEPER_UNVERIFIED` | 소유 프로세스나 전용 interop 연결을 확인할 수 없습니다. 다른 터미널의 interop 소켓을 대신 쓰지 않습니다. |
| `WSL_PROCESS_STILL_RUNNING`, `WSL_PROCESS_STOPPED_KEEPER_UNVERIFIED` | 중지 확인이 완료되지 않았습니다. 실행 소유 기록을 보존합니다. |

진단은 관리 OpenCode 서버 시작·중지, 모델 호출, 브라우저 조작을 하지 않습니다. 실행 파일 버전과 WSL 전제 조건 확인을 위한 짧은 프로세스는 실행하며, 지정 WSL 배포판이 꺼져 있으면 해당 호출로 시작될 수 있습니다. 다른 WSL 작업이 열려 있다면 배포판 전체 종료나 재시작을 해결 절차로 사용하지 마세요. 지원 요청에는 위 보고서의 오류 코드를 사용하고 `runtime.json` 전체를 보내지 않습니다.


사용 절차는 [사용 설명서](./user-guide.md), 설치·업데이트·제거는 [설치 안내](../README-install.md), 배포별 변경은 [변경 기록](../CHANGELOG.md)을 참고하세요.

문제를 확인할 때는 **Chrome 확장 → Bridge → OpenCode 실행 환경 → 브라우저 MCP → 모델** 순서로 구분합니다. 패널 상단의 **연결됨**은 Bridge 연결 상태입니다. 이것만으로 OpenCode나 모델이 준비됐다는 뜻은 아닙니다.

## 설치 위치에서 소유자·권한 오류가 남

설치 마법사에서 **기본 위치로 되돌리기**를 누르면 현재 사용자의 `%LOCALAPPDATA%\AgentBrowser`를 선택합니다. 새 설치는 위치 선택 후 **다음 → 설치**로 진행하며 Bridge를 먼저 시작할 필요가 없습니다.

권한 오류에는 문제가 된 설치 폴더 또는 상위 폴더의 경로를 표시합니다. 다른 사용자가 소유하거나 파일·폴더를 교체할 수 있는 경로는 사용할 수 없습니다. GUI와 PowerShell 모두 같은 신뢰 기준을 적용하며 기존 폴더의 소유자·권한을 자동 변경하지 않습니다. 사용할 경로가 거부되면 허용된 개인 전용 로컬 폴더를 선택합니다. 드라이브 문자만으로 허용·거부를 결정하지 않습니다.

## 1. 우선 확인할 것

1. 패널의 **브라우저** 탭에서 **현재 작업**과 **최근 작업 기록**을 확인합니다. 원하지 않는 작업이 진행 중이면 맨 위 **중단**을 누릅니다.
2. **설정 → Bridge 페어링**의 연결 상태와 사이드 패널의 실행 환경 이름 아래 OpenCode 연결 상태를 각각 확인합니다.
3. 설정의 **연결 진단 → 진단 실행**을 누릅니다. 진단은 모델 요청을 보내지 않습니다. Bridge에 연결되지 않으면 먼저 아래 Bridge 연결 문제를 해결합니다.
4. 오류 메시지, 발생 시각, 선택한 실행 환경과 대화, 실패한 도구 이름을 확인합니다.

`EXECUTION_UNKNOWN`이나 제출 직후 연결 끊김이 있었다면 같은 지시를 바로 다시 보내지 마세요. 실행 여부가 불명확하므로 페이지·처리 내역부터 확인해야 합니다.

## 2. 확장이 없거나 패널이 열리지 않음

| 증상 | 확인·조치 |
|---|---|
| 확장 아이콘이 없음 | Chrome 확장 프로그램 메뉴에서 AgentBrowser를 고정합니다. `chrome://extensions`에서 설치·사용 상태도 확인합니다. |
| 확장을 로드할 수 없음 | ZIP 전체를 압축 해제하고 설치를 마친 뒤, 설치 폴더의 `extension`을 선택했는지 확인합니다. `manifest.json`이 그 폴더 바로 아래 있어야 합니다. |
| 업데이트했는데 이전 화면이 표시됨 | `chrome://extensions`에서 AgentBrowser를 새로고침한 뒤 패널을 다시 엽니다. 진행 중인 작업은 먼저 중단합니다. |
| 다른 Chrome 프로필에 설치됨 | 실제 작업할 Chrome 프로필에서 확장을 로드합니다. 여러 프로필이 연결되어 있으면 패널의 **브라우저 → 이 브라우저 사용** 선택도 확인합니다. |
| 개발자 모드·로컬 확장 로드가 차단됨 | 조직 정책을 확인합니다. AgentBrowser에서 정책을 우회하지 않으며 담당자에게 승인된 배포 방식을 확인해야 합니다. |

지원 기준은 Chrome 116 이상입니다. 패널을 닫아도 서버 작업과 브라우저 제어는 계속될 수 있으므로, 패널을 닫는 것을 중단 방법으로 사용하지 마세요.

## 3. Bridge 연결·페어링 문제

### 연결 끊김 또는 계속 재시도

설치 마법사에서 기존 설치를 선택하고 **기존 설치의 연결 설정...**을 누릅니다. **Chrome 확장 추가** 화면에서 **다음**을 누르면 Bridge가 자동으로 시작됩니다. 이어지는 **Chrome 연결** 화면의 주소를 확장 옵션에 입력합니다. 기본값은 `ws://127.0.0.1:4317/extension`이며 끝의 `/extension`도 필요합니다. OpenCode 서버 주소인 `http://127.0.0.1:4096`을 넣으면 안 됩니다.

목록에 없는 사용자 지정 설치라면 **다음**으로 설치 위치 화면을 열어 실제 경로를 입력하고, **뒤로**를 눌러 첫 화면의 **기존 설치의 연결 설정...**을 선택합니다. 다른 폴더의 Bridge를 임의로 실행하거나 설치 파일만 이동하지 마세요.

### 상호 인증 실패·페어링 필요

**페어링 인증 실패**, **상호 인증에 실패했습니다**, **다른 확장과 페어링되어 있습니다**가 표시되면 다음을 확인합니다.

1. 같은 배포 버전의 Bridge와 확장을 사용 중인지 확인합니다. 업데이트 후 확장도 새로고침합니다.
2. 설치 마법사에서 해당 설치를 선택하고 **기존 설치의 연결 설정... → 다음**으로 **Chrome 연결** 화면을 열어 주소와 토큰을 확인합니다.
3. **Bridge 주소**와 **페어링 토큰**을 입력하고 **저장 후 연결**을 누릅니다. 토큰은 출력된 64자리 소문자 16진수 값 그대로 사용합니다.
4. 실제 작업할 Chrome 프로필인지 확인합니다. 다른 확장 설치와 다시 페어링하면 기존 연결에 영향을 줄 수 있습니다.

토큰을 주소의 쿼리 문자열에 붙이지 마세요. 기존 토큰을 유지하면서 주소만 수정할 때는 토큰 입력란을 비워둘 수 있습니다. 토큰을 입력하지 않았는데 새로 페어링된 것으로 간주하지 않습니다.

### 설치 시작 직후 GetFullPath 경로 형식 오류

v0.1.3 이하에서 Windows PowerShell 5.1의 `powershell -File .\setup.ps1` 실행이 `GetFullPath`의 “경로의 형식이 잘못되었습니다” 오류로 중단될 수 있습니다. advanced script의 매개변수 기본값에서 `$PSScriptRoot`가 비는 결함이며 v0.1.4에서 설치·제거 스크립트의 기본 경로를 본문에서 초기화하도록 수정했습니다. 최신 Windows ZIP 전체를 별도 폴더에 풀고 [설치 안내](../README-install.md)에 따라 `AgentBrowser-Setup.exe`를 실행합니다.

기존 v0.1.3 ZIP으로 진행해야 한다면 압축 해제 폴더에서 기존 설치 명령 끝에 `-PackageDir .`을 추가할 수 있습니다. 설치 위치를 바꾸는 옵션은 `-InstallDir`이며 `PackageDir`는 ZIP을 푼 원본 폴더를 뜻합니다. 이 오류를 해결하려고 전역 실행 정책이나 Chrome 정책을 변경할 필요는 없습니다.

### PowerShell이 스크립트 실행을 차단함

현재 ZIP의 네이티브 `AgentBrowser-Setup.exe`를 사용합니다. GUI는 PowerShell 스크립트를 실행하지 않습니다. 오류 해결을 위해 실행 정책을 영구 변경하지 않습니다. 스크립트가 필요한 경우 승인된 실행 방법을 사용합니다. 조직 정책이 EXE 또는 로컬 확장 실행도 차단한다면 담당자에게 승인된 설치 방법을 확인합니다.

### WSL 설정 저장 실패

기존 WSL UNC 파일에 Windows `File.Replace`를 적용하면 지원하지 않는 작업 오류가 날 수 있습니다. 현재 설치 관리자는 같은 디렉터리의 임시 파일과 Linux rename으로 변경하고 기존 소유자·그룹·권한을 보존합니다. 미리보기 이후 파일이 바뀌면 중단하므로 **뒤로 → 다음**으로 새 내용을 확인합니다. 선택한 WSL 사용자의 권한이 없으면 권한·정책을 우회하지 않고 중단합니다.

## 4. Bridge는 연결되지만 OpenCode가 준비되지 않음

설정에서 해당 프로필의 **편집**으로 값을 확인하고 **프로필 저장 → 시작·연결 확인**을 실행합니다. 사이드 패널의 **대화 → 실행 설정 → 실행 환경**과 다른 프로필을 점검하고 있지 않은지도 확인하세요.

### 실행 파일·작업 디렉터리 오류

**OpenCode 실행 파일의 절대 경로**에는 OpenCode 파일을 넣어야 합니다. AgentBrowser의 `browser-bridge.exe`나 `opencode serve`라는 명령 문자열을 넣지 않습니다. 파일·폴더가 실제로 존재해야 하며 로그인 시 PATH가 터미널과 같다고 가정하지 않습니다.

Windows 네이티브 예시:

```powershell
Get-Command opencode -All | Select-Object CommandType, Source
Test-Path -LiteralPath 'C:\Tools\OpenCode\opencode.exe'
Test-Path -LiteralPath 'C:\Work\project'
& 'C:\Tools\OpenCode\opencode.exe' --version
```

예시 경로를 실제 설치 경로로 바꿉니다. 명령 검색 결과가 함수나 별칭이라면 그것을 실행 파일 경로로 사용하지 않습니다. `.cmd` 실행기는 지원하지만 경로에 `%`, `!`, `&` 등 명령 해석 문자가 있으면 사용할 수 없습니다. 이 경우 실제 OpenCode `.exe` 경로를 확인하세요.

WSL 예시:

```powershell
wsl.exe --list --verbose
wsl.exe --distribution Ubuntu --exec /bin/sh -lc 'command -v opencode'
wsl.exe --distribution Ubuntu --exec /home/user/.opencode/bin/opencode --version
wsl.exe --distribution Ubuntu --exec /usr/bin/test -d /home/user/project
```

배포판 이름과 Linux 경로를 실제 값으로 바꿉니다. 특정 Linux 사용자가 필요하면 해당 프로필의 **WSL 사용자(선택)**를 맞춥니다. 셸에서 검색된 경로를 기록한 뒤 **절대 경로**로 실행되는지도 확인합니다. WSL 프로필에는 `C:\...`가 아닌 `/home/...` 같은 Linux 경로가 필요합니다.

WSL interop이 막혀 있거나 Windows에서 WSL localhost로 접근할 수 없으면 자동 실행·브라우저 MCP가 실패할 수 있습니다. 이를 해결하려고 서버를 임의로 `0.0.0.0`에 열거나 방화벽·TLS 검증을 끄지 마세요. 해당 환경의 WSL·네트워크 정책을 확인합니다.

### 포트·환경변수·인증 오류

관리 서버의 **포트(선택)**를 비우면 자동 선택합니다. 고정 포트가 필요하면 다른 프로그램이 사용하지 않는 포트를 지정합니다. 다른 프로그램의 프로세스를 임의로 종료하지 않습니다. 기존 프로필의 실행 설정을 바꿨다면 진행 중인 작업을 마친 후 **서버 중지 → 시작·연결 확인**으로 반영합니다.

터미널에서만 동작한다면 OpenCode가 필요로 하는 환경변수·프록시·인증서 설정을 확인합니다. **추가 환경변수(JSON)**는 `{"NAME":"value"}`처럼 문자열 값이어야 합니다. 비밀번호·환경변수 필드를 비워 저장하면 기존 값을 유지하므로 이를 비밀값 삭제 방법으로 사용하지 마세요.

**이미 실행 중인 서버**는 서버 관리자가 먼저 실행해야 합니다. 주소는 서버 루트의 HTTP(S) 주소를 사용하고 `/api` 등 경로 접두사, 쿼리 문자열, 주소 안의 인증정보를 넣지 않습니다. 401 또는 403이 나면 오류가 OpenCode 서버 인증에서 나온 것인지 모델 공급자에서 나온 것인지 먼저 구분합니다.

## 5. 브라우저 MCP·Bridge 포트 변경 문제

대화는 가능하지만 브라우저 도구가 없거나 **browser MCP is unavailable or not connected**가 나오면 **대화 → 작업 도구 → 커맨드·스킬·MCP**와 연결 진단을 확인합니다.

- 진단은 등록 없음·비활성·실행 파일 없음·권한·인증·타임아웃·연결 실패를 구분합니다. 전역 JSON에 `mcp`가 없어도 관리 서버는 별도 overlay를 사용할 수 있으므로 해당 프로필의 진단 결과를 확인합니다.
- Windows·WSL 관리 프로필: 해당 서버에 Bridge의 MCP 설정이 제공되어야 합니다. 실행 파일·배포판·interop 상태와 진단 오류를 확인합니다.
- 외부 서버·독립 CLI: 해당 OpenCode 설정에 브라우저 MCP를 별도로 등록해야 합니다. 설치 GUI에서 실제 Windows·WSL 설정 파일을 선택해 등록합니다. 사용자 전체 설정을 덮어쓰지 않습니다.
- **different Bridge port or a removed Bridge executable** 오류: 관리 서버가 이전 Bridge 주소나 사라진 실행 파일을 계속 사용 중입니다. 해당 프로필의 **서버 중지 → 시작·연결 확인**을 실행해 새 MCP 설정을 적용합니다.

설치 후 Bridge 포트를 바꾸려면 새 ZIP의 GUI에서 같은 설치 폴더를 선택하고 **업데이트**를 선택합니다. 설치 위치 화면의 **고급 설정...**에서 새 **Bridge 포트**를 지정하고 **확인**으로 창을 닫은 뒤 **다음 → 업데이트**로 적용합니다. 변경 전 진행 중인 작업을 중단합니다. 변경 후 **Chrome 확장 추가 → 다음**으로 **Chrome 연결** 화면을 열어 새 주소를 확장에 저장하고, 관리 프로필마다 **서버 중지 → 시작·연결 확인**을 진행합니다. 외부 서버·CLI도 새 주소로 다시 연결해야 합니다.

정상 업데이트는 기존 관리 서버가 참조하는 버전별 Bridge 실행 파일을 보존합니다. 설치 폴더의 `app` 안에서 이전 버전 exe를 임의로 삭제하지 마세요.

## 6. 모델이 없거나 실제 요청이 실패함

### 모델 목록이 비어 있음

먼저 **대화 → 실행 설정 → 실행 환경**이 맞는지 확인합니다. 모델 목록은 선택한 OpenCode에 연결된 provider 설정을 사용합니다. AgentBrowser 설정에 API 키를 새로 넣거나 외부 모델을 자동 추가하지 않습니다. 기존 OpenCode에서 provider·모델·인증 설정을 점검하세요.

이전 대화에 저장된 모델이 현재 환경에 없으면 **실행 설정 → 모델·에이전트 → 모델**에서 직접 선택합니다. 사용 가능한 다른 모델로 조용히 바뀌었다고 가정하지 않습니다.

### HTTP 403 `FreeTierError`

Zen 무료 모델 목록 조회가 성공해도 실제 요청이 허용되는 것은 아닙니다. 이 프로젝트의 기존 무료 모델 파일럿은 HTTP 403 `FreeTierError`로 종료되어 브라우저 도구 호출에 도달하지 못했습니다. 이후 실제 모델 작업 검증은 사용자가 배포 환경에서 수행합니다.

이는 Bridge 페어링 토큰을 다시 입력해서 해결할 오류가 아닙니다. 현재 계정의 OpenCode·Zen 이용 조건과 요청 허용 여부를 확인하고 오류가 지속되면 멈춥니다. 제한을 우회하거나 유료 모델로 자동 전환하지 않습니다. 개인 무료 검증에서는 주 모델뿐 아니라 제목 생성 등 보조 작업의 모델 설정도 확인해야 합니다.

### 서버는 정상인데 답변·도구 수행만 실패함

연결 진단은 모델 요청을 보내지 않습니다. 진단 통과와 실제 모델의 도구 수행 성공은 별개입니다. 선택한 모델·에이전트와 오류 원문, 도구 카드가 생겼는지를 확인합니다. 공급자 인증·한도·모델 미지원 오류와 도구의 페이지 접근 오류를 구분하세요.

응답이 멈춘 것처럼 보이면 **답변이 필요합니다**, **권한 확인** 카드가 있는지도 확인합니다. 완료되지 않은 요청을 CLI에서 처리했다면 패널을 다시 열어 서버 상태를 조회할 수 있습니다.

화면이 **응답 중**인데 서버 작업이 끝난 것으로 보이면 먼저 대화 영역을 아래로 스크롤하고 잠시 상태 갱신을 기다립니다. 실행 중인 선택 세션은 약 2초 간격으로 메시지·상태를 다시 조회하고, 화면 복귀 때도 확인합니다. 전송 직후에는 초기 이벤트가 없어도 제한된 시간 동안 확인합니다. **응답 중단**은 실제 중단 요청이므로 새로고침 버튼처럼 사용하지 마세요. 계속 일치하지 않으면 패널을 다시 열고 발생 시각·실행 환경·세션과 오류 정보를 확인합니다. 이 재조회는 이벤트 누락에 대비한 복구이며, 과거에 보고된 표시 지연의 정확한 원인이 모두 확인됐다는 뜻은 아닙니다.

## 7. 페이지 읽기·조작 오류

| 오류·증상 | 다음 조치 |
|---|---|
| `UNSUPPORTED_PAGE` | Chrome 설정·새 탭·확장 프로그램·Chrome Web Store 등 제한 페이지인지 확인합니다. 일반 HTTP/HTTPS 페이지를 연 뒤 URL·제목을 지정해서 다시 요청합니다. 오류 카드의 **오류 세부 정보**에서 기술 정보를 확인할 수 있습니다. |
| `TAB_NOT_FOUND`, `TAB_CLOSED` | 남은 대상이 없거나 지정 탭이 닫혔습니다. 탭 목록의 살아 있는 HTTP(S) 탭을 명시적으로 선택하거나 새 탭에서 계속하도록 지시합니다. |
| `STALE_ELEMENT` | 페이지·요소가 바뀌었거나 탭 닫기 뒤 이전 대상으로 복귀했습니다. 새 스냅샷을 읽고 대상을 확인한 뒤 조작합니다. |
| `FRAME_UNAVAILABLE` | iframe의 접근 권한·sandbox·로딩 상태를 확인합니다. 접근할 수 없는 프레임을 읽었다고 간주하지 않습니다. |
| `ELEMENT_NOT_INTERACTABLE` | 요소가 보이는지, 비활성·가려짐·다른 화면 상태인지 확인합니다. 비슷한 다른 요소를 임의로 누르지 않습니다. |
| `NEEDS_TAB_ACTIVATION` | 화면 캡처할 작업 탭을 활성화한 뒤 다시 읽도록 지시합니다. |
| `BROWSER_BUSY` | 같은 요청에 작업이 이미 있으면 기존 operationId로 계속합니다. 다른 요청의 작업이라면 완료·중단 후 시작합니다. |
| `BROWSER_DISCONNECTED` | Bridge와 확장 연결을 복구한 뒤 작업 탭·페이지 상태를 다시 확인합니다. |
| `TIMEOUT`, `CANCELLED` | 대기 조건·작업 상태를 확인합니다. 클릭·제출이 포함됐다면 실행 여부부터 확인합니다. |
| `EXECUTION_UNKNOWN` | 실행됐을 수도 있고 아닐 수도 있습니다. 페이지·서버 처리 내역을 확인하기 전 같은 클릭·제출·삭제를 반복하지 않습니다. |

에이전트 조작으로 열린 새 탭은 출처가 확인된 경우에만 작업에 자동 추가됩니다. 동시 사용자 입력·원본 변경·로딩 시간 초과 경고가 있으면 탭 목록을 먼저 확인하고 명시적으로 연결·전환하도록 지시합니다. 원래 탭의 요소 참조를 새 탭에서 재사용하지 않습니다.

페이지가 요구하는 실제 사용자 입력, closed Shadow DOM, canvas 기반 화면, OS 대화상자는 자동화에 제한이 있습니다. **현재 탭** 첨부는 최대 16,000자의 본문 텍스트이며 페이지 전체의 실시간 상태가 아닙니다. 필요한 영역을 브라우저 도구로 다시 읽도록 지시하세요.

## 8. 중단했는데 화면이나 결과가 바뀜

맨 위 **중단**은 이후 브라우저 조작을 차단합니다. 이미 웹사이트에 제출한 요청의 처리나 완료된 결과는 취소하지 않습니다. 화면이 늦게 바뀌었다면 이전 요청의 결과인지 확인하세요.

입력란의 **응답 중단**은 선택한 OpenCode 대화의 응답을 멈춥니다. 브라우저 작업의 소유 세션과 선택한 대화가 다를 수 있습니다. 외부 CLI에서 시작한 작업의 세션을 패널이 식별하지 못하면 맨 위 **중단**은 해당 CLI 대화를 임의로 종료하지 않습니다. 필요한 경우 원래 CLI에서 응답을 중단합니다.

**이전으로 되돌리기**도 웹사이트에서 이미 완료한 작업을 되돌리는 기능이 아닙니다. 사이트 자체의 취소·복구 기능이 필요한지는 실제 처리 상태를 보고 결정하세요.

## 9. 진단 수집과 문의

설정의 **진단 실행**에서 실패한 항목을 확인합니다. 연결되지 않거나 공유용 결과가 필요하면 **설치 폴더의 `diagnose.cmd`를 두 번 클릭**합니다. 업데이트가 막혔으면 새 ZIP의 `diagnose.cmd`에서 기존 설치를 선택합니다.

`data\diagnostic-report.json`은 허용된 검사·상태·오류 코드·버전과 익명 프로필 번호만 담습니다. 이 파일과 원본 `doctor --json`·제품 로그는 다릅니다. 원본 진단은 로컬 점검용 경로·주소를 포함할 수 있으므로 그대로 공유하지 않습니다. 로그는 설치 폴더의 `data\logs`에 있습니다.

문의에는 다음을 포함하면 원인을 좁히기 쉽습니다.

- AgentBrowser 배포 버전, Chrome 버전, OpenCode 버전.
- Windows 네이티브·WSL·외부 서버 중 실행 방식. 실제 계정·배포판 이름·작업 경로는 생략합니다.
- 실패한 단계와 시각, 오류 코드, 재현할 수 있는 최소 절차.
- 연결 진단의 실패 항목, 모델 요청 이전인지 이후인지, 브라우저 도구가 실제 실행됐는지.

페어링 토큰, 비밀번호, 인증 헤더, API 키, 환경변수 값, 실제 대화·웹페이지 원문을 포함하지 마세요. 로그·진단에 비밀값이 숨겨져 있어도 경로·서버 주소·프로젝트명은 조직 정보를 담을 수 있으므로 공유 전에 확인합니다. 설치 데이터 폴더 전체나 OpenCode 전체 설정을 그대로 첨부하지 않습니다.


## 10. 화면 구성·스크롤·테마

새 화면은 **대화**, **세션**, **브라우저** 탭으로 나뉩니다. **세션** 목록은 상위 대화만 보여줍니다. 하위 에이전트 대화를 찾으려면 부모 세션 왼쪽 화살표를 펼칩니다. 펼친 뒤 새 하위 작업이 생겼다면 접었다 다시 펼쳐 갱신합니다. 선택한 하위 대화에서 **상위 세션으로**를 사용해 부모로 돌아갈 수 있습니다. 예전에 대화 아래에 있던 설정은 **실행 설정**, 사용량·파일 변경·셸·커맨드는 **작업 도구**로 옮겼습니다. 화면 전체를 끝까지 스크롤해서 찾을 필요가 없습니다. **대화로 돌아가기** 또는 **Esc**로 메시지 화면으로 돌아옵니다.

대화 내용과 세션 목록·브라우저 기록은 각 화면 안에서 따로 스크롤합니다. 대화 입력란과 맨 위 브라우저 **중단**은 대화가 길어져도 접근할 수 있습니다. 이전 메시지를 읽는 중에는 새 메시지에 맞춰 자동으로 아래로 이동하지 않으므로, 최신 응답을 확인하려면 대화 영역을 아래로 스크롤하세요.

테마 변경은 실행 환경 이름 오른쪽 **테마** 또는 설정 페이지의 **테마**에서 합니다. **시스템 설정**은 Chrome이 감지한 시스템 밝기 설정을 따라 Latte/Mocha로 바뀝니다. 항상 같은 색을 쓰려면 Latte·Frappé·Macchiato·Mocha 중 하나를 선택합니다. 이전 버전의 밝게/어둡게 선택은 Latte/Mocha로 이어집니다.

업데이트 후에도 이전의 긴 한 페이지 화면이 보이면 `chrome://extensions`에서 확장을 새로고침하고 패널을 다시 엽니다. 로드한 확장 경로가 실제 설치 폴더의 `extension`인지 확인하세요. 새로고침 전에 진행 중인 작업을 멈추고 미전송 초안은 별도로 보관합니다.


## iframe에서 읽기는 되지만 클릭·본문 열기가 실패함

먼저 새 snapshot에서 해당 프레임과 요소를 다시 찾습니다. 본문 확인은 그 프레임의 frameRef로 기다리며, 페이지 이동 후 이전 문서의 참조를 재사용하지 않습니다. 일반 행에 클릭 의미나 초점 표시가 없으면 모델이 클릭 후보를 찾지 못할 수 있습니다. `isTrusted` 검사나 브라우저 사용자 활성화가 필요한 앱은 합성 클릭으로 해결되지 않습니다. 이 경우 실제 사용자 입력이 필요하며 Chrome 보안 설정 변경이나 권한 우회를 해결책으로 안내하지 않습니다.

## 새 요청의 탭 예약이 남음

전송 여부가 불확실한 네트워크 오류는 자동 재전송하지 않습니다. 해당 세션에서 응답 중단을 누르고 다시 요청합니다. 중단은 먼저 브라우저 예약을 닫습니다. OpenCode 중단 API까지 실패하면 오류와 요청 신원을 유지하므로 연결 복구 후 중단을 재시도할 수 있습니다. 완료 응답이 없는 idle 상태만으로 다른 요청의 예약을 빼앗지 않습니다.

v0.1.6부터 완료된 요청은 패널이 닫힌 동안에도 확인해 정리합니다. 삭제·중지·오류 상태의 실행 환경은 예약을 정리하지만 일시적인 통신 오류나 시작 중 상태에서는 보존합니다. Stop을 처리하는 동안에는 중복 클릭을 막습니다. 이전 요청을 중단한 직후 같은 연결에서 요청 ID 없는 새 브라우저 작업은 30초 동안 거부될 수 있으므로 패널에서 새 요청을 명시적으로 시작하세요.


## WSL은 응답하지만 브라우저 MCP가 준비되지 않음

진단에서는 OpenCode HTTP 인증/health와 브라우저 MCP 연결 상태를 구분합니다. HTTP가 정상이어도 MCP 초기화가 실패하면 준비 완료가 아닙니다. 이 경우에도 doctor는 MCP 세부 원인(executable_missing, permission_denied, connection_timeout 등)을 표시합니다. WSL 프로필의 Bridge 데이터 home은 WSL이 마운트한 Windows 드라이브 경로여야 하며, 지원하지 않는 UNC/확장 경로는 INVALID_PARAMS로 반환합니다. 전용 keeper 소켓의 Windows canary가 실패하거나 소유권이 불명확하면 오류를 유지합니다. 해당 실행 환경을 명시적으로 중단한 뒤 다시 시작하고, 반복되면 Windows·WSL·커널·OpenCode 버전과 민감정보를 제거한 오류 코드를 확인하세요. 전역 OpenCode 설정, 운영 프로세스, WSL 전체 인스턴스를 임의로 지우거나 재시작하지 마세요.

WSL 제어 호출은 같은 합성 fixture 비교에서 시작 6→2회, 일반 상태 확인 5회 합계 15→5회였습니다. 이는 전체 WSL 실행 횟수가 아니라 제어 호출 수이며, 별도 장기 keeper 세션 1개가 추가됩니다. 지연 시간 개선을 모든 PC에서 보장하는 수치는 아닙니다.


## 새 탭을 열려는데 requestId 오류가 남

패널은 메시지를 전송할 때 요청 ID를 만듭니다. 이 ID는 탭마다 만드는 값이 아닙니다. 새 탭을 여는 첫 `browser_tabs new`도 현재 요청 ID를 사용하며, 먼저 기존 페이지에 연결하거나 읽을 필요가 없습니다. 작업이 시작되면 같은 operationId로 추가 탭 생성·선택·닫기를 이어갑니다. 모델이 빠뜨리거나 이전 요청 ID를 재사용하면 탭을 만들기 전에 거부합니다.

최신 버전으로 업데이트하고 확장을 새로고침한 뒤 새 메시지로 다시 요청합니다. 오류가 계속되면 해당 도구 이름·오류 코드만 확인합니다. 사용자가 ID를 만들어 입력하거나 토큰을 바꿀 필요는 없습니다.

## 링크·팝업을 닫은 뒤 작업이 이어지지 않음

v0.1.9부터 현재 작업에서 명시적으로 방문했던 살아 있는 탭으로 돌아갑니다. 중첩 팝업은 최근 방문 순서로 복귀합니다. 자동 복귀 뒤에는 페이지를 다시 읽기 전 변경·닫기를 거부합니다. 돌아갈 탭이 없으면 같은 작업에서 새 탭을 만들거나 목록의 기존 HTTP(S) 탭을 명시적으로 선택합니다. 다른 Chrome 프로필의 탭을 대신 고르지 않습니다.

닫기는 현재 선택된 작업 탭만 대상으로 합니다. 다른 탭을 닫으려면 먼저 그 탭으로 전환해야 합니다. 편집된 폼·접근할 수 없는 프레임이 있으면 닫지 않으며 Chrome의 닫기 경고도 자동 승인하지 않습니다. 경고를 취소했거나 `EXECUTION_UNKNOWN`이면 탭 목록을 확인하고 다른 탭에서 작업을 계속할 수 있습니다.

## 스크립트 업데이트가 관리 런타임 기록 때문에 멈춤

새 Bridge 경로나 포트에 기존 OpenCode가 계속 연결되는 것을 막기 위한 검사입니다. 진행 중인 작업을 마치고 확장 옵션에서 관리 프로필의 **서버 중지**를 완료한 뒤 재시도합니다. 자동 관리 서버 전환은 GUI 업데이트를 사용합니다. 상태·소유권 오류로 중지할 수 없다면 `diagnose.cmd`로 코드를 확인하며 기록을 강제 삭제하지 않습니다. `-NoStart`도 이 검사를 생략하지 않습니다.

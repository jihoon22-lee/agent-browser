# AgentBrowser 사용 설명서

AgentBrowser는 기존 OpenCode v1 에이전트가 Windows Chrome의 페이지를 읽고 조작하도록 연결하고, Chrome 사이드 패널에서 대화와 작업을 관리하는 도구입니다. OpenCode의 모델·인증·에이전트 설정을 사용합니다.

설치·업데이트·제거는 [설치 안내](../README-install.md), 오류 해결은 [문제 해결](./troubleshooting.md), 버전별 변경은 [변경 기록](../CHANGELOG.md)을 참고하세요.

## 화면 구성과 테마

기본 화면은 **대화**입니다. 대화 내용만 가운데 영역에서 스크롤하고, 메시지 입력란은 아래에 유지됩니다. 이전 메시지를 읽으려고 위로 스크롤하면 새 응답이 와도 읽던 위치를 유지합니다.

| 위치 | 하는 일 |
|---|---|
| **대화** 탭 | 지시 입력, 응답·도구 결과 확인, 질문·권한 응답 |
| **세션** 탭 | 대화 찾기·새로 만들기·이름 변경·분기·삭제·내보내기 |
| **브라우저** 탭 | 브라우저 선택, 현재 작업 탭, 최근 작업 기록 확인 |
| 입력창 아래 선택란 | 다음 메시지의 모델·에이전트·variant 선택, 모델 검색·즐겨찾기 |
| 대화의 **실행 설정** | 실행 환경·작업 디렉터리 선택 |
| 대화의 **작업 도구** | 사용량·컨텍스트, 작업·파일 변경, 셸, 커맨드·스킬·MCP 확인 |
| 실행 환경 이름 오른쪽 **테마** | 화면 색상 변경 |
| 맨 위 **설정** | Bridge 페어링·OpenCode 프로필·진단 |
| 맨 위 **중단** | 어느 탭에서든 현재 브라우저 작업 중단 |

실행 설정·작업 도구·테마 화면에서는 **대화로 돌아가기** 또는 **Esc**로 돌아옵니다. 탭에 키보드 초점이 있으면 좌우 화살표로 이동하고 **Home/End**로 첫 번째·마지막 탭을 선택할 수 있습니다. 화면을 오가도 열린 패널의 대화와 작성 중인 초안은 유지됩니다.

**테마**에서 **시스템 설정**, **Latte · 밝은 테마**, **Frappé · 부드러운 다크**, **Macchiato · 깊은 다크**, **Mocha · 짙은 다크**를 선택할 수 있습니다. 시스템 설정은 밝은 모드에서 Latte, 어두운 모드에서 Mocha를 사용합니다. 선택은 저장되며 설정 페이지의 테마와도 동기화됩니다.

## 1. 처음 한 번 준비하기

### 이미 설치한 경우

Windows에 로그인한 뒤 Chrome에서 AgentBrowser 아이콘을 눌러 사이드 패널을 엽니다. 상단이 **연결됨**이고 실행 환경 이름 아래에 OpenCode 연결 상태가 표시되면 [첫 브라우저 작업](#3-첫-브라우저-작업)을 시작할 수 있습니다.

확장 아이콘이 보이지 않으면 Chrome 도구 모음의 확장 프로그램 메뉴에서 AgentBrowser를 고정합니다. Bridge가 시작되지 않았으면 설치 마법사에서 **기존 설치의 연결 설정 → 다음**으로 진행하면 자동으로 시작됩니다. 매번 OpenCode 서버를 터미널에서 따로 시작할 필요는 없습니다.

### 새로 설치하는 경우

Windows x64, Chrome 116 이상, 기존 OpenCode v1 설치가 필요합니다. Windows 네이티브 OpenCode 사용자는 WSL을 설치할 필요가 없습니다. AgentBrowser 실행에는 Node.js·Rust·Python이 필요하지 않습니다.

1. 배포 ZIP을 임시 폴더에 모두 압축 해제하고 [설치 안내](../README-install.md)에 따라 `AgentBrowser-Setup.exe`를 실행합니다. 기본 설치 위치는 `%LOCALAPPDATA%\AgentBrowser`입니다.
2. 마법사의 **Chrome 확장 페이지 열기**를 누릅니다. 열린 `chrome://extensions`에서 **개발자 모드**를 켜고 **압축해제된 확장 프로그램 로드**를 누른 뒤 **Alt+D**로 복사된 설치 폴더의 `extension` 경로를 붙여 넣습니다. 임시 압축 해제 폴더를 선택하지 않습니다. 추가되면 마법사에 ✓ 표시가 나타납니다.
3. **Chrome 연결** 단계에서 **Chrome에 연결**을 누릅니다. 6자리 코드가 표시되고 확장 설정이 열립니다.
4. 설정의 **Bridge 페어링 → 페어링 코드**에 코드를 입력하고 **코드로 연결**을 누릅니다. 연결되면 마법사가 다음 단계로 넘어갑니다. 코드가 통하지 않으면 마법사의 **토큰 복사**로 주소·토큰을 직접 입력하고 **저장 후 연결**을 누릅니다.
5. 아래 실행 환경을 마법사에서 저장합니다.

페어링 토큰은 로컬 브라우저 제어에 사용하는 비밀값입니다. 대화, 화면 공유, 오류 보고에 포함하지 마세요. Chrome 정책이 개발자 모드나 로컬 확장 로드를 차단한다면 조직의 승인된 설치 절차가 필요합니다.

## 2. OpenCode 실행 환경 등록하기

설치 마법사의 **OpenCode 설정** 단계에서 찾은 OpenCode를 확인하고 **저장하고 연결 확인**을 누르면 기본 실행 환경으로 저장되고 바로 시작·연결 확인까지 진행됩니다. 결과와 저장된 목록이 같은 화면에 표시되며 Chrome 설정에도 같은 목록이 보입니다. 확장 설정의 **OpenCode 실행 환경**에서 **프로필 추가**로 직접 추가하거나 기존 프로필을 수정할 수도 있습니다. 패널에 실행 환경이 하나도 없으면 **실행 환경 추가** 버튼이 표시됩니다. 프로필은 어떤 OpenCode를 어느 작업 디렉터리에서 실행할지 저장하는 설정입니다.

| 항목 | 입력 내용 |
|---|---|
| **ID** | 영문·숫자·밑줄·하이픈으로 만든 식별자. 예: `work-wsl` |
| **이름** | 패널에서 구별할 이름. 예: `업무 프로젝트` |
| **실행 방식** | **Windows 네이티브**, **WSL**, **이미 실행 중인 서버** 중 선택 |
| **작업 디렉터리** | 해당 OpenCode가 사용할 실제 프로젝트의 절대 경로 |
| **기본 실행 환경으로 사용** | 기본으로 선택할 프로필인지 지정 |

### Windows 네이티브

**OpenCode 실행 파일의 절대 경로**에 설치된 `opencode.exe` 또는 지원되는 `.cmd` 실행기의 전체 경로를 입력합니다. 예를 들어 `C:\Tools\OpenCode\opencode.exe`와 `C:\Work\project`를 사용할 수 있습니다. 예시 경로를 그대로 복사하지 말고 실제 파일과 폴더를 지정하세요. `opencode serve`처럼 명령과 인수를 한 필드에 넣지 않습니다.

### WSL

**WSL 배포판**에는 실제 배포판 이름을 입력합니다. **OpenCode 실행 파일의 절대 경로**와 **작업 디렉터리**는 해당 배포판 안의 Linux 경로입니다. 예: `/home/user/.opencode/bin/opencode`, `/home/user/project`. 필요한 경우 **WSL 사용자(선택)**도 지정합니다.

Bridge는 Windows에서 실행하고 기존 WSL OpenCode를 시작합니다. WSL interop과 Windows에서 WSL 서버로의 localhost 연결이 가능해야 합니다. Windows 경로를 Linux 실행 파일 필드에 넣거나, 배포판이 다른 파일 경로를 섞지 않습니다.

### 이미 실행 중인 서버

기존 OpenCode v1 서버를 관리하는 사용자는 **서버 주소**를 입력합니다. 주소는 `http://127.0.0.1:4096` 같은 서버 루트 주소여야 합니다. `/api` 같은 경로 접두사나 주소 안의 비밀번호는 지원하지 않습니다. 인증이 필요하면 **인증·환경변수·포트** 안의 **인증 사용자**, **새 비밀번호**를 사용합니다.

외부 서버는 AgentBrowser가 시작·종료하지 않습니다. 브라우저 도구를 사용하려면 서버의 기존 OpenCode 설정에 브라우저 MCP를 별도로 등록해야 합니다. [설치 안내의 MCP 연결](../README-install.md)을 참고하세요.

### 저장하고 연결 확인하기

**프로필 저장** 후 목록의 **시작·연결 확인**을 누릅니다. **준비됨** 표시 후 사이드 패널의 **대화 → 실행 설정 → 실행 환경**에서 해당 프로필을 선택하고 **대화로 돌아가기**를 누릅니다. Windows·WSL 관리 서버에는 Bridge가 브라우저 MCP 설정을 별도로 제공하며 기존 모델·provider·다른 MCP 설정을 대체하지 않습니다.

추가 환경이 필요하면 **추가 환경변수(JSON)**에 문자열 값의 JSON 객체를 입력합니다. 프로필 편집에서 비밀번호와 환경변수 필드를 비워두면 기존 값을 유지합니다. **포트(선택)**를 비우면 관리 서버의 포트를 자동 선택합니다. 이것은 **Bridge 주소**의 포트와 별개입니다.

## 3. 첫 브라우저 작업

처음에는 공개 페이지를 읽는 작업으로 연결을 확인하세요. 실제 모델의 도구 선택과 작업 수행은 사용 환경에서 확인해야 합니다. 연결 진단의 성공은 모델 작업 성공을 의미하지 않습니다.

1. Chrome에 비민감한 일반 HTTP/HTTPS 페이지를 엽니다. 예를 들어 `https://example.com`을 사용할 수 있습니다.
2. 사이드 패널의 **대화 → 실행 설정**에서 **실행 환경**과 **프로젝트·실행 정보** 안의 작업 디렉터리를 확인하고 **대화로 돌아가기**를 누릅니다.
3. 세션이 없어도 첫 메시지를 보내면 새 세션이 자동으로 만들어집니다. 따로 시작하려면 **세션** 탭의 **새 세션**이나 대화 화면의 **새 대화 시작**을 누릅니다.
4. **실행 설정 → 모델·에이전트**에서 기존 OpenCode에 연결된 **모델**과 사용할 **에이전트**를 선택합니다. 개인 무료 모델 검증이라면 현재 사용 가능한 Zen 무료 모델인지 확인합니다. 특정 모델이 목록에 있다는 것만으로 무료 요청이나 도구 호출이 허용되는 것은 아닙니다.
5. **대화로 돌아가기**를 누른 뒤 다음 예시를 입력하고 **보내기**를 누릅니다.

   > 현재 페이지의 제목과 본문을 세 문장으로 요약해줘.

   도구 결과에는 페이지 스냅샷과 열린 탭 목록이 함께 담기므로, 에이전트는 별도 조회 없이 다음 동작을 이어 갈 수 있습니다.

6. 대화에 표시된 도구 카드를 열어 실제 읽기 결과와 오류를 확인합니다. **브라우저** 탭에서 **현재 작업**의 작업 탭, **최근 작업 기록**의 도구 실행도 확인합니다. 답변만 있고 도구 호출이 없다면 브라우저 읽기까지 확인된 것은 아닙니다.
7. 답변의 제목·URL·내용을 실제 페이지와 비교합니다. 질문이나 권한 요청이 나타나면 내용을 확인하고 응답합니다.

여러 Chrome 프로필이 연결되어 있으면 **브라우저** 탭의 **연결된 브라우저**에 목록이 나타납니다. 작업을 시작하기 전에 사용할 프로필의 패널에서 **이 브라우저 사용**을 선택합니다. 진행 중인 작업이 있을 때는 브라우저를 바꿀 수 없습니다.

작업 탭이 연결된 뒤 사용자가 다른 탭을 보더라도 에이전트의 작업 대상은 고정됩니다. 새 작업에서 다른 탭을 다루려면 대상 URL·제목을 명확하게 지시하고 작업 탭을 확인하세요.

에이전트의 클릭·키 입력으로 새 탭이 열린 것이 확인되면 새 탭을 같은 작업에 추가하고 그 탭에서 이어갑니다. 원래 탭도 작업에 남습니다. 새 탭에서는 이전 페이지의 요소 참조를 쓰지 않고 새 스냅샷을 읽어야 합니다. 같은 시점에 사용자가 클릭했거나 원본 페이지가 바뀌었거나 로딩 제한시간을 넘겨 출처가 불명확하면 자동으로 연결하지 않고 경고합니다. 이때 탭 목록을 확인한 뒤 대상 탭 연결·전환을 명시적으로 지시하세요.

## 4. 메시지와 참조 입력

**Enter**는 전송, **Shift+Enter**는 줄바꿈입니다. 한글 조합 중 Enter는 전송하지 않습니다. 모델·에이전트·variant 변경은 다음 메시지에 적용됩니다. **즐겨찾기 추가**로 모델을 표시하고 **모델 검색**으로 찾을 수 있습니다. 이전 세션의 모델을 현재 환경에서 사용할 수 없으면 사용할 모델을 직접 선택해야 합니다.

| 입력 방법 | 전달되는 내용 |
|---|---|
| **현재 탭** 또는 `@` 목록의 **@현재탭 · 브라우저 관찰** | 현재 대상 페이지의 제목·URL·본문 텍스트 첨부 |
| **선택 영역** 또는 **@선택영역 · 브라우저 관찰** | 현재 대상 페이지에서 선택한 텍스트 첨부 |
| **파일·이미지** | 사용자가 고른 로컬 파일. 파일당 최대 10 MiB |
| `@` 입력 후 **서버 파일** 선택 | 선택한 OpenCode 실행 환경의 파일 내용을 첨부 |
| `@` 입력 후 **에이전트** 선택 | 해당 에이전트 참조 추가 |

**현재 탭**과 **선택 영역**은 누른 시점의 관찰 텍스트를 첨부합니다. 이 브라우저에 연결된 작업이 있으면 그 작업 탭을, 없으면 활성 탭을 읽습니다. 본문·선택 텍스트는 최대 16,000자이며 화면 캡처나 전체 프레임 스냅샷이 아닙니다. 이후 페이지가 바뀌어도 첨부 내용이 자동 갱신되지 않습니다. 페이지의 최신 구조를 읽고 조작하려면 메시지에서 브라우저 도구 사용을 지시하세요.

첨부는 **보내기** 전에 이름 옆의 **×**로 제거할 수 있습니다. 파일과 페이지 내용은 선택한 OpenCode와 모델이 처리할 입력이므로 의도한 내용인지 확인하세요. 이미지 등 각 형식의 이해 가능 여부는 모델에 따라 다릅니다.

작성 중인 초안과 첨부는 열린 패널 안에서 실행 환경·작업 디렉터리·세션별로 구분합니다. 패널을 닫거나 확장을 새로고침한 뒤에도 미전송 초안이 보존된다고 가정하지 마세요. 필요한 내용은 전송하거나 별도로 보관하세요.

## 5. 질문·권한 요청과 중단

**답변이 필요합니다** 카드에서는 질문별 선택지를 고르거나 허용된 경우 **직접 답변**을 작성한 뒤 **답변 제출**을 누릅니다. 복수 선택 질문은 여러 항목을 고를 수 있습니다. 답변하지 않을 때는 **질문 취소**를 사용합니다. CLI에서 이미 처리한 요청이면 중복 응답하지 않고 상태를 다시 확인합니다.

**권한 확인** 카드에서는 **요청 대상**, **도구·명령과 세부 범위**, **기억할 범위**를 확인합니다.

- **한 번 허용**: 이번 요청을 허용합니다.
- **이 규칙 기억**: 서버가 표시한 규칙 범위에 OpenCode의 `always` 응답을 보냅니다. 모든 작업을 영구 허용하는 버튼이 아닙니다.
- **거부**: 해당 권한 요청을 거부합니다.

중단 버튼은 위치에 따라 대상이 다릅니다.

| 버튼 | 중단 대상 |
|---|---|
| 입력란 아래 **응답 중단** | 선택한 대화 세션의 OpenCode 응답을 중단. 현재 브라우저 작업이 이 세션의 것이면(또는 소유를 알 수 없고 다른 세션이 실행 중이 아니면) 후속 브라우저 조작도 먼저 차단. 다른 세션의 브라우저 작업은 건드리지 않음 |
| 맨 위 고정된 **중단** | 표시된 브라우저 작업의 후속 조작을 차단. 작업과 연결된 OpenCode 세션을 식별할 수 있을 때만 그 세션도 중단 |
| 설정 프로필의 **서버 중지** | Bridge가 시작한 해당 OpenCode 서버를 종료. 개별 응답을 멈추는 버튼과 다름 |

선택한 대화와 브라우저 작업의 소유 세션이 다를 수 있으므로 작업 탭과 대화 제목을 확인하세요. 외부 CLI에서 시작한 작업의 세션을 식별할 수 없으면 맨 위 **중단**은 임의의 대화를 종료하지 않습니다.

중단은 이미 제출된 웹사이트 요청이나 완료된 변경을 되돌리지 않습니다. 수동으로 이어서 작업할 때는 먼저 중단 상태와 페이지의 현재 상태를 확인하세요. 패널을 닫는 것만으로 작업이 중단되지는 않습니다.

### 신뢰 입력과 작업 탭 묶음(설정에서 켬)

일부 사이트는 확장이 보내는 일반 클릭을 무시합니다. 그런 사이트에서 버튼이 반응하지 않으면 설정의 **신뢰 입력 사용(디버거)**을 켜세요. 켜면 다음과 같이 동작합니다.
- 에이전트의 클릭·키 입력이 실제 사용자 입력처럼 전달됩니다.
- 작업 중 뜬 알림창(alert)은 확인하고, 확인창(confirm)은 취소한 뒤 결과로 알립니다.
- 비활성 작업 탭도 화면을 캡처할 수 있습니다.

작업 중인 탭 위에는 Chrome이 "AgentBrowser가 이 브라우저를 디버깅하는 중" 표시줄을 띄웁니다. 표시줄의 **취소**를 누르면 그 작업은 일반 입력으로 계속하고, 작업이 끝나면 디버거는 바로 분리됩니다. 기본은 꺼져 있습니다.

### 파일 업로드

에이전트에게 웹사이트에 파일을 올려 달라고 할 때는 그 파일을 메시지에 **첨부**해서 보내세요. 에이전트는 **그 요청에 첨부한 파일만** 페이지의 파일 선택 칸에 넣을 수 있습니다. 컴퓨터의 다른 파일을 찾거나 경로로 읽지 않습니다. 요청이 끝나면 그 첨부는 더 이상 올릴 수 없으니, 다시 올리려면 새 요청에 다시 첨부합니다. 파일당 10 MiB, 요청당 5개(합계 25 MiB)까지이며, 페이지 안의 다른 사이트 영역(광고 등)에는 넣지 않습니다.

설정의 **작업 탭 묶음 허용**을 누르면 에이전트가 작업 중인 탭을 "AgentBrowser" 탭 그룹으로 묶습니다. 작업이 끝나면 직접 묶은 탭만 풉니다.

### 작업 표시와 잠시 넘겨받기

에이전트가 작업 중인 탭에는 파란 테두리와 "AgentBrowser 작업 중" 표시가 나타나고, 클릭하는 순간 대상 요소가 잠깐 노란 테두리로 강조됩니다. 이 표시는 화면에만 보이며 페이지 내용 읽기나 클릭에는 영향을 주지 않습니다. 확장 아이콘에는 상태가 나타납니다.

| 아이콘 표시 | 뜻 |
|---|---|
| ● | 이 브라우저에서 작업 중 |
| ! | 에이전트가 질문·권한 응답을 기다림. 패널을 열어 답하세요 |
| ‖ | 사용자가 넘겨받아 조작 중 |

로그인·캡차·결제 확인처럼 직접 해야 하는 단계가 나오면 입력란 아래 **잠시 넘겨받기**를 누르고 브라우저를 조작합니다. 그동안 에이전트의 브라우저 도구 호출은 기다립니다. 끝나면 **이어서 진행**을 누르세요. 기다리던 에이전트는 바뀐 페이지를 다시 읽은 뒤 이어 갑니다. 45초 넘게 넘겨받고 있으면 에이전트는 "사용자가 조작 중"이라는 안내를 받고 잠시 뒤 다시 시도합니다.

응답 중단을 처리하는 동안 버튼은 비활성화됩니다. 실패가 표시되면 연결 상태를 확인한 뒤 다시 시도하세요. 완료 확인이 느려도 브라우저 중단은 그 조회를 기다리지 않습니다. 패널을 닫아도 완료된 요청은 background에서 확인해 정리하며, Chrome의 실행 일정에 따라 표시 갱신이 늦을 수 있습니다.

## 6. 세션을 이어 쓰고 결과 저장하기

**세션** 탭에서 **세션 검색**과 **검색**으로 기존 대화를 찾고 목록에서 선택합니다. 선택하면 대화 화면으로 돌아옵니다. 목록과 검색에는 상위 세션만 표시하며, 최근 50개부터 불러오고 **더 보기**로 50개씩 범위를 늘립니다. 각 행에는 마지막 갱신 시각과 실행 중 여부, 하위 세션 개수가 표시됩니다.

하위 에이전트 세션이 있는 세션에만 왼쪽 화살표가 나타납니다. 화살표를 펼치면 하위 세션이 나오고, 하위 세션에 다시 하위 세션이 있으면 그 행에도 화살표가 나타납니다. 펼칠 때마다 서버에서 새로 조회합니다. 하위 대화를 열면 원래 제목과 내용이 유지되며 **상위 세션으로**를 눌러 한 단계 위로 돌아갈 수 있습니다.

세션 관리는 각 행 오른쪽의 **⋯**(세션 작업) 버튼이나, 대화 제목 옆의 **⋯**(현재 세션 작업) 버튼에서 합니다.

- **이름 변경**: 그 자리에서 이름을 편집합니다. **Enter**로 저장하고 **Esc**로 취소합니다. 한글 조합 중 Enter는 저장하지 않습니다.
- **전체 분기**: 해당 대화를 바탕으로 새 세션을 만듭니다.
- **JSON 내보내기**: 세션 정보와 메시지 데이터를 저장합니다. **Markdown 내보내기**는 대화의 텍스트를 저장합니다.
- **삭제**: 메뉴 안에서 **삭제 확인**을 한 번 더 눌러야 삭제됩니다. 해당 세션과 대화 기록이 지워지며, 나머지 목록은 그대로 유지됩니다. 필요한 내용은 먼저 내보내세요.

메시지에 마우스를 올리거나 키보드 초점을 옮기면 메시지 작업 버튼이 나타납니다.

- 내 메시지의 **여기서 분기**: 해당 지점에서 분기하고, 메시지를 편집해서 다시 보낼 수 있도록 입력란에 준비합니다.
- 내 메시지의 **이전으로 되돌리기**: OpenCode 대화와 서버 파일 변경을 해당 메시지 이전으로 되돌리는 요청입니다. 웹사이트에서 끝난 클릭·제출·삭제는 되돌리지 않습니다. 되돌린 상태에서는 **되돌리기 취소**를 사용할 수 있습니다.
- 응답 아래의 **복사**: 한 응답의 여러 단계에 나뉜 텍스트를 한 번에 복사합니다. 텍스트가 없는 응답(도구 호출만 있는 단계)에는 표시하지 않습니다.

한 응답이 여러 단계로 나뉘어 있어도 하나의 응답으로 묶어 보여 줍니다. 모델이 추론 내용을 보낸 경우에만 **추론 과정**이 표시됩니다. 도구 카드 제목 아래에는 대상 URL·요소·명령 등 주요 입력이 한 줄로 표시되며, 카드를 펼치면 입력과 결과 전체를 볼 수 있습니다.

도구 카드의 **결과 복사**, **결과 내보내기**는 도구 출력을 저장합니다. 구조화된 표 추출 결과에는 **표 CSV**, **표 Markdown**이 표시됩니다. 임의의 답변이나 모든 화면 표에 자동으로 이 버튼이 생기는 것은 아닙니다.

파일 결과에는 다운로드 링크가 표시됩니다. 서버 파일인 경우 **서버 파일 열기**로 해당 OpenCode 실행 환경에서 읽고 **파일 내려받기** 또는 **내용 복사**를 사용합니다. 텍스트 미리보기나 긴 도구 출력은 화면에서 잘릴 수 있으므로 전체 내용은 다운로드로 확인하세요.

## 7. 반복 작업과 고급 기능

**대화 → 작업 도구 → 커맨드·스킬·MCP**에서 기존 OpenCode에 등록된 커맨드·스킬·MCP 상태를 확인합니다. `/`를 입력하면 명령 자동완성이 나타납니다. `/new`, `/sessions`, `/models`, `/skills`, `/commands`는 패널 기능을 열고, `/compact`는 선택한 모델로 컨텍스트 압축을 요청합니다. 등록된 사용자 커맨드는 이름 뒤에 인수를 입력해 실행합니다.

실행 가능한 스킬·MCP 프롬프트는 서버의 커맨드를 사용합니다. 별도 스킬 항목의 **스킬 첨부**는 정의를 입력에 첨부하므로 작업 내용을 작성하고 보내야 합니다. 설정에 없는 커맨드를 패널이 새로 만들지는 않습니다.

**작업 도구 → 사용량·컨텍스트**에는 최근 호출, 현재 사용자 요청 합계, 세션 누적, 캐시·추론 토큰이 표시됩니다. **현재 컨텍스트**는 최근 호출 기반 추정치이며 모델 한도와 다를 수 있습니다. 모델 변경 직후에는 새 호출을 기다려야 합니다. **지금 컨텍스트 압축**은 모델 요청을 발생시킬 수 있습니다.

**작업 도구 → 작업·하위 작업·파일 변경**에서 할 일, 하위 세션, 파일 변경을 확인합니다. **셸 명령 → 셸 실행**은 선택한 환경의 작업 디렉터리에서 실제 명령을 실행합니다. 대화형 터미널·외부 편집기는 기존 OpenCode CLI를 사용하며, 연결 명령은 **실행 설정 → 프로젝트·실행 정보**에서 확인합니다.

일상 사용은 Chrome 패널을 열고 실행 환경을 확인한 뒤 **세션** 탭에서 기존 대화를 선택하면 됩니다. 응답 중인 세션은 스트림 외에도 주기적으로 상태를 확인합니다. 전송 직후 이벤트가 빠진 경우와 화면으로 돌아온 경우에도 서버의 메시지·상태를 다시 조회하므로, 완료된 답변을 보기 위해 **응답 중단**을 누를 필요는 없습니다. 패널을 다시 열면 서버의 대화와 미응답 요청을 다시 조회합니다. 같은 서버에 연결된 CLI와 함께 사용할 수 있지만, 독립적으로 실행한 모든 CLI 세션이 자동으로 같은 서버에 합쳐지지는 않습니다.

## 8. 현재 범위와 제한

일반 HTTP/HTTPS 페이지를 대상으로 합니다. Chrome 설정 페이지, Chrome Web Store 등 제한 페이지, OS 파일 선택창·인증서 대화상자·브라우저 자체 UI는 일반 페이지처럼 제어할 수 없습니다. iframe은 접근 권한과 프레임 상태의 영향을 받고, closed Shadow DOM·canvas 중심 UI·실제 사용자 입력을 강제하는 웹앱에는 제한이 있습니다.

스크린샷은 작업 탭의 활성화가 필요할 수 있습니다. 다른 탭의 화면을 작업 결과로 대신 반환하지 않습니다. 브라우저 동시 작업은 충돌을 막기 위해 제한되며, 작업 도중 대상 브라우저를 임의로 바꾸지 않습니다.

모델의 도구 선택과 작업 품질은 사용하는 모델과 OpenCode 설정에 따라 다릅니다. AgentBrowser는 공급자 제한을 우회하거나 유료 모델로 자동 전환하지 않습니다. 사용 중 문제가 생기면 [문제 해결](./troubleshooting.md)을 확인하고 이슈로 알려 주세요.


## 새 요청의 기본 작업 탭

특정 탭을 지정하지 않고 새 요청을 보내면 전송 당시 포커스된 Chrome 창의 활성 탭을 사용합니다. 특정 탭을 요청하면 그 대상이 우선합니다. 요청을 수행하는 도중 다른 탭을 보더라도 진행 중인 작업 대상은 바뀌지 않습니다. 다음 요청을 보낼 때 현재 활성 탭을 다시 선택합니다.

기본 탭을 안전하게 확인할 수 없거나 그 탭이 닫혔으면 다른 탭을 임의로 조작하지 않습니다. 대상 탭을 지정하거나 해당 페이지를 활성화한 뒤 다시 요청하세요. 다른 요청이 브라우저를 사용 중이면 완료를 기다리거나 그 요청의 응답을 중단해야 합니다. 서버 응답 유실로 완료 여부를 확인하지 못한 경우에도 임의로 이전 작업을 이어가지 않습니다.


## iframe 메일함과 입력 제한

접근 가능한 같은 출처·다른 출처·중첩 iframe에서 요소를 읽고 클릭할 수 있습니다. iframe 안의 좌표로 클릭하며 필요한 스크롤을 적용합니다. 표준 링크·버튼 외에 명시적 클릭 이벤트 속성 또는 키보드 초점이 있는 항목도 후보에 포함합니다. 이벤트를 상위 노드에만 등록하고 아무 의미·초점 표시도 없는 일반 행은 자동으로 발견하지 못할 수 있습니다.

본문이 iframe에 나타나면 그 프레임 안에서 기다립니다. 새 문서로 이동하거나 프레임이 닫히면 이전 참조를 재사용하지 않고 다시 읽어야 합니다. 접근이 막힌 프레임은 snapshot의 오류로 표시합니다.

클릭은 합성 DOM 이벤트입니다. 좌표를 전달해도 `event.isTrusted`는 false이며, 실제 사용자 입력만 허용하는 앱·브라우저 UI·사용자 활성화가 필요한 기능은 지원을 보장하지 않습니다. debugger 권한이나 Chrome 보안 설정을 추가하지 않습니다. 실제 업무 서비스는 이번 검증에 접속하지 않았습니다.


## WSL 런타임 호환과 진단

Bridge가 시작한 WSL OpenCode는 전용 keeper 세션으로 Windows MCP 실행 소켓을 유지합니다. HTTP health만 성공해서 준비 완료로 표시하지 않고 브라우저 MCP 연결까지 확인합니다. 같은 런타임의 상태 확인·재사용은 기존 소유 프로세스를 유지하며, 소유권이 불확실하면 자동으로 다른 프로세스를 종료하거나 새 서버를 만들지 않습니다. 먼저 해당 실행 환경의 중단·진단 결과를 확인하세요.

이번 검증 환경은 Windows 11 10.0.26200.9457, WSL 2.7.12.0, Ubuntu 실행 커널 6.18.33.2-microsoft-standard-WSL2, OpenCode 1.18.29입니다. 별도 구형 WSL VM, 실제 WSL shutdown, 커널 vsock 결함·자원 고갈은 시험하지 않았습니다. 이전 부팅 복구 시험은 격리 메타데이터 주입입니다. 사용자 WSL 업데이트나 보안 설정 변경을 요구하지 않습니다.

## 게시판 목록 복귀와 탭 닫기

글을 읽은 뒤 목록으로 돌아올 때 방문 기록을 한 항목씩 이동합니다. 지연된 목록·정렬·페이지 변경 뒤에는 예상 내용이 나타날 때까지 기다리고 다시 읽어 대상을 찾습니다. 이전 요소 번호나 바뀐 링크의 참조로 계속 클릭하지 않습니다.

처음 연결한 탭, 기존 다른 탭, 새로 연 탭 사이를 한 작업에서 오갈 수 있습니다. 다른 탭을 닫으려면 그 탭을 명시적으로 선택한 뒤 닫습니다. 현재 탭을 닫으면 작업에서 최근 방문했던 살아 있는 탭으로 복귀하고 페이지를 다시 읽은 뒤 이어갑니다. 돌아갈 대상이 없으면 새 탭이나 목록의 기존 탭을 선택합니다. 닫기는 진행 중인 요청 자체를 끝내지 않습니다.

예를 들어 “목록에서 상품 A를 새 탭으로 열어 가격을 읽고, 이미 열린 상품 B와 비교한 다음, 목록에 메모를 저장하고 상세 탭들을 닫아줘”처럼 연속해서 요청할 수 있습니다. 작업 도중 사용자가 상세 탭을 닫아도 최근 작업 대상으로 복귀해 다시 읽고 계속합니다. 화면의 탭을 직접 활성화하는 것과 에이전트의 작업 대상 선택은 별개입니다.

편집된 일반 폼이나 Chrome 닫기 경고가 있으면 강제로 닫지 않습니다. 경고를 취소하거나 닫힘을 확인하지 못하면 현재 탭 상태부터 확인합니다. 사이트 자체 상태나 비표준 편집기의 미저장 데이터, 검사 뒤 동시에 바뀐 편집 내용까지 판정하는 기능은 아닙니다.
## 새 탭과 즐겨찾기

새 탭은 기존 페이지를 먼저 연결하거나 읽을 필요 없이 요청할 수 있습니다. Chrome 새 탭 화면에서도 대상 웹 주소로 새 작업을 시작할 수 있습니다. 요청 ID는 패널이 전달하므로 직접 입력하지 않습니다. 주소를 지정하거나 빈 탭을 만든 뒤 원하는 웹 주소로 이동할 수 있습니다. 여러 창이 있으면 창 목록에서 대상 창을 지정할 수 있습니다. 일반 링크를 새 탭으로 열 때는 현재 페이지의 링크 참조를 사용합니다.

즐겨찾기는 확장 설정의 **즐겨찾기 접근 허용**을 누르고 Chrome 동의 창을 직접 승인한 뒤 사용할 수 있습니다. Chrome 권한 자체는 읽기와 변경을 포함하지만 AgentBrowser 도구는 목록·검색·폴더 읽기만 제공합니다. 제목과 URL은 요청한 작업의 연결된 모델에 전달될 수 있습니다. **즐겨찾기 접근 해제**로 철회할 수 있습니다.

빈 탭 생성/웹 이동과 달리 about:blank의 DOM 검사는 Chrome이 거부합니다. 이 페이지의 안전한 닫기는 지원하지 않으며 강제 닫기로 우회하지 않습니다. 다운로드 관리·로컬 파일 업로드·OS 단축키 등은 지원 범위를 구분해야 합니다. 자세한 표와 권한 영향은 [브라우저 작업 지원표](./browser-capabilities.md)를 확인하세요.

## 고급 브라우저 기능 (Chrome 125 이상)

확장 **설정 → 고급 브라우저 기능 → 고급 기능 사용**을 켭니다. 텍스트·프레임 신뢰 입력, 전체·영역 캡처, 화면 좌표 조작, 웹페이지 대화상자 응답에는 **신뢰 입력**도 켜야 합니다. Chrome의 디버거 표시가 나타날 수 있습니다. 기존 기능은 Chrome 116 이상에서 사용할 수 있습니다.

입력창에는 선택한 모델의 이미지 입력 지원 여부가 표시됩니다. 화면 좌표 조작에는 현재 요청에서 실제 사용하는 모델의 이미지 입력과 도구 호출 지원이 필요합니다. 지원 정보가 없거나 다른 모델로 실행되면 조작이 제한될 수 있습니다. 보조 모델을 자동 호출하지 않습니다. 화면이 바뀌거나 캡처를 한 번 사용했다면 새 캡처로 다시 판단합니다. 전체 페이지 캡처는 읽기용이며 좌표 입력에는 화면 또는 영역 캡처를 사용합니다.

confirm·prompt가 열리면 작업 결과와 **브라우저** 탭에 대기 상태가 표시됩니다. 확인·취소 또는 prompt의 응답을 명시합니다. 대화상자 응답 뒤 실제 페이지 결과를 다시 확인합니다. 작업과 연결되지 않은 대화상자, beforeunload, OS 창과 Chrome 권한 창은 사용자가 처리합니다. 알림창(alert)은 작업과 연결된 경우 자동 확인할 수 있습니다.

다운로드는 설정에서 **다운로드 접근 허용**을 직접 누르고 Chrome의 선택 권한에 동의합니다. 디버거 없이도 사용할 수 있습니다. 페이지에서 다운로드를 시작한 뒤 **브라우저** 탭의 후보 중 작업에 맞는 파일을 선택합니다. 선택 전 후보는 해당 작업의 완료 근거가 아닙니다. 연결한 ID로 진행·완료·중단을 확인하며, 저장 위치 선택이나 Chrome 경고는 사용자가 처리합니다. Chrome의 완료는 저장 완료 상태이며 현재 파일의 존재나 내용을 검사한 결과는 아닙니다. 접근 권한은 같은 설정에서 해제할 수 있습니다.

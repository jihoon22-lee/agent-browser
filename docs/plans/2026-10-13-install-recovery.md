# 사내 설치·WSL 실패 복구와 진단 배포

사용자는 사내 지정 `D:\Multimedia\AgentBrowser` GUI 설치가 소유자 검사에 막혀 배포된 PowerShell 설치기로 진행했다. 기존 Startup 링크 충돌(-NoStartup)과 실행 정책 옵션 안내 누락 이후 설치·페어링·WSL 프로필 저장은 진행됐으나 시작·중지·삭제가 모두 WSL 상태 확인 실패로 막혔다. Ubuntu-24.04의 사용자와 프로필 사용자는 같고 Windows에서 배포판 호출 및 설치 data/runtime 디렉터리 조회는 된다. 실제 사내 원인은 아직 확정하지 않았다. 다른 WSL 작업은 중지하지 않는다.

사용자는 제대로 시험한 배포, 완전한 스크립트 설치 문서와 문제 검증 도구를 요청했다. 긴 명령 입력과 사진 전달을 요구하지 않는다.

- [x] WSL 명시 사용자·실패한 시작 기록·중지·삭제·재등록 회귀를 작성하고 합성 오류를 재현한다.
- [ ] 실제 사내 장애 원인을 새 진단 결과로 확정한다. 로컬 재현 실패를 해결 완료로 표시하지 않는다.
- [x] 구체적인 WSL 상태 진단과 실행 전 검증을 구현한다. 검증되지 않은 프로세스 강제 종료나 실행 기록 무조건 삭제는 사용하지 않는다.
- [x] 사내 관리 설치 경로·기존 Startup 충돌을 처리하는 설치 동선과 PowerShell 대안을 정리한다.
- [x] 비밀값을 제외한 결과와 오류 코드를 표시하는 간단한 배포 진단 도구를 포함한다.
- [x] PowerShell 설치·시작·페어링·업데이트·제거 및 진단 절차를 배포 문서에 수록한다.
- [x] 실제 Windows exe + 격리 WSL에서 성공/실패/복구를 검증한다. 기존 운영 설치·WSL 다른 작업·전역 OpenCode 설정을 보존한다.
- [x] 새 버전 PR/CI와 게시할 ZIP 설치·진단·복구 검증 후 v0.1.8 Release를 게시하고 게시본을 재검증한다.

실제 사내 PC 접근과 별도로 가져온 Ubuntu-24.04 검증을 구분해 status에 기록한다. 이전 v0.1.7 Windows 성공 결과를 이번 장애의 재현/해결 증거로 대신하지 않는다.

# 배포 문서·PR·CI·main 반영 계획

사용자 추가 요청(2026-10-11): 실제 Chrome 연결 순서를 즉시 안내하고, CHANGELOG를 포함한 배포 문서를 검토·작성하며 기존 문서도 갱신한다. PR을 생성하고 CI 결과를 확인·수정한 뒤 main에 머지한다.

## 범위

- 기존 v0.1.0 설치·태그·zip의 이력을 보존한다. 문서 포함 배포는 새 패치 버전으로 발행한다.
- 이미 설치된 사용자 Bridge와 현재 Chrome 작업을 이 문서 작업 때문에 중단하지 않는다.
- 모델 호출 없이 문서·패키징·CI를 검증한다. 기존 실제 Windows 검증과 원격 CI 증거를 구분한다.
- 라이선스는 기존 workspace의 MIT 선언과 실제 package 메타데이터·LICENSE를 맞춘다.

## 실제 사용 피드백 반영 — 남은 작업 순서 (2026-10-11)

문서/CI만 완료하고 머지하지 않는다. 아래 사용자 보고와 사용성 요구를 같은 PR의 완료 조건에 추가한다.

1. **응답 표시 지연**: 서버에서 약 8초에 완료된 첫 응답이 사용자에게 10–30초 동안 보이지 않았음.
   Chrome 내부 페이지의 `UNSUPPORTED_PAGE`는 정상 차단이나 지연과 구분한다.
   실제 OpenCode의 생성 이벤트를 외부 LLM 없이 재현하고 표시 경로를 검증한다.
   느린 todo/children/diff가 메시지·SSE를 막는 재현은 수정했으며 실제 신고 원인으로 단정하지 않는다.
2. **오류 안내**: tool의 `state.error` JSON 문자열과 completed 상태의 `{ok:false}`를 읽기 쉬운 오류로 표시한다.
   제한 페이지에는 일반 HTTP/HTTPS 페이지를 열도록 안내하고 기술 상세는 필요할 때 펼친다. 회귀 테스트로 검증한다.
3. **새 탭 링크 이어가기**: 현재 작업에서 target=_blank 또는 window.open으로 열린 탭을 식별해 이어서 읽고 조작한다.
   실제 Chrome에서 새 탭 생성·새 문서 참조·원래 탭 복귀를 확인한다. 관련 없는 사용자 새 탭은 가져오지 않는다.
   중단·닫힘·지연 팝업·다른 Chrome 프로필 경합의 소유권을 검토한다.
4. **패널 정보 구조**: 대화 / 세션 / 브라우저 작업을 분리한다. 환경·모델과 고급 기능은 별도 제어 영역으로 이동한다.
   메시지 영역과 작업 기록은 각자 스크롤하며 입력창과 핵심 중단 동작은 긴 대화에서도 접근 가능하게 유지한다.
   기존 기능을 삭제하거나 새 화면 뒤에 접근 불가능하게 만들지 않는다.
5. **테마·시각 검증**: 출처/라이선스를 확인한 Catppuccin 4개 팔레트와 시스템 선택을 검토·적용한다.
   실제 사용하는 본문/보조문구/버튼/입력/코드/오류/선택/포커스 색상 조합을 검사한다.
   일반 텍스트 대비 4.5:1, 필요한 UI 경계·상태 대비 3:1을 기준으로 부족한 조합을 조정한다.
   320/400/600px 패널에서 각 테마의 긴 대화·긴 기록·키보드 탐색을 실제 Chrome으로 확인한다.
   대비 검사만으로 전체 WCAG 준수를 주장하지 않는다.
6. **원격 CI의 실제 실패 해결**: 첫 PR CI에서 Windows 초기화 잠금의 AccessDenied 경합과 Linux 시작 테스트 시간 초과가 발생.
   Windows 경합은 재현/수정했고 Linux fixture에는 상태·stderr 진단과 실제 시작 계약에 맞춘 기한을 넣었다.
   테스트를 건너뛰거나 실패를 성공으로 바꾸지 않고 새 원격 결과를 확인한다.
7. **문서·통합·배포 마감**: 화면 변경에 맞게 가이드/CHANGELOG/설치/상태를 다시 맞춘다.
   라이선스 고지·zip 포함·독립 검토 → 최종 PR CI 통과 → main 머지 → main CI/정확한 태그의 0.1.1 배포와 해시 확인.

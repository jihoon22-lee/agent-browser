## 검토 결과: 다음 개선 후보(우선순위순)

### 성능

1. **응답 중 2초 주기 전체 메시지 재조회**: busy/retry 동안 `/session/:id/message`로 전체 기록을 다시 받아 모든 메시지 객체를 교체한다.
   긴 세션일수록 네트워크·파싱·렌더링 비용이 커진다. 개선 방향은 두 가지다.
   - SSE 이벤트가 최근에 도착했으면 주기 조회를 건너뛴다.
   - v1의 `limit`·`before`로 마지막 일부만 받아 병합한다.
   - 내용이 같은 메시지는 객체 정체성을 유지한다.
2. **긴 세션 초기 로딩**: 세션을 열 때 전체 메시지를 받는다. 최근 N개만 받고 위로 스크롤하면 이전 메시지를 받는 방식(`before`)과
   가상 스크롤을 검토한다.
3. **스트리밍 delta 렌더 묶기**: delta 이벤트마다 dispatch·렌더한다. requestAnimationFrame 단위로 묶으면 긴 응답의 CPU 사용이 줄어든다.
4. **reducer의 `seen` 배열**: 이벤트마다 5,000개 배열을 검색·복사한다. 클라이언트가 이미 Set으로 중복을 제거하므로 reducer 쪽 처리를 축소할 수 있다.
5. **숨겨진 서랍 패널의 매 렌더 재생성**: 작업 도구 패널의 `JSON.stringify(mcp)`, diff, 커맨드 목록을 보이지 않아도 매번 만든다. 열려 있을 때만 렌더한다.

### 기능

1. **대화 맨 아래로 이동 버튼**: 위쪽을 읽는 중에 새 응답이 오면 "새 메시지 ↓" 버튼을 띄운다.
2. **도구 호출 요약 개선**: 브라우저 도구(`browser_click`, `browser_snapshot` 등)를 "클릭 · 검색 버튼"처럼 사람이 읽는 한 줄로 보여 준다.
   관련 탭으로 이동하는 동작도 검토한다.
3. **실행 중 응답 시간·단계 표시**: 응답 중 경과 시간과 현재 실행 중인 도구 이름을 상태 표시줄에 보여 준다.
4. **세션 목록 정보 보강**: 상대 시간("3분 전"), 실행 중 표시, 하위 세션 개수를 보여 준다. 디렉터리가 같으면 경로를 생략한다.
5. **메시지 편집 후 다시 보내기**: 사용자 메시지의 "분기"를 "편집" 흐름으로 묶는다. 되돌리기 후 입력창에 원문을 채운다.
6. **window.confirm 대체**: 삭제·되돌리기 확인을 패널 안의 인라인 확인으로 바꾼다. 사이드 패널에서 브라우저 대화상자를 쓰면 흐름이 끊긴다.
7. **키보드 단축키**: 새 세션(Ctrl+Shift+O), 세션 탭 전환, 응답 중단(Esc 두 번) 등.
8. **알림**: 패널이 숨겨진 상태에서 응답이 끝나거나 질문·권한 요청이 오면 Chrome 알림 또는 배지로 알린다.

### 디자인

1. **Markdown 렌더러 보강**: 중첩 목록, 링크 자동 인식, 코드 블록 언어 표시와 접기, 긴 표의 가로 스크롤 표시.
2. **헤더 밀도**: 앱 헤더·탭·작업 공간 요약·실행 설정 칩·대화 제목이 위쪽 세로 공간을 많이 차지한다. 요약과 칩을 한 줄로 합치는 방안을 검토한다.
3. **도구 카드 상태 아이콘**: 텍스트 상태(대기/실행 중/완료/오류) 대신 아이콘과 색을 쓰고 실행 중에는 진행 표시를 둔다.
4. **빈 상태와 오류 안내**: 연결 실패·모델 없음·Bridge 끊김에 맞는 다음 동작 버튼(설정 열기, 다시 시도)을 둔다.
5. **브라우저 탭 화면**: 타임라인 항목을 대화의 도구 호출과 연결하고 실패 항목을 강조한다.

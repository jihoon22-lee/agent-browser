# 브라우저 품질 측정과 개선

상태: 진행 중. 원장: `docs/handoff.md`, 조사: `docs/review-browser-performance-2026-10-22.md`.

사용자 요청: 제안한 지표를 볼 수 있는 반복 테스트·결과 수집을 구성하고 측정에 근거한 개선까지 진행한다.

## 완료 조건

- [ ] 독립된 합성 브라우저 benchmark: JSON 원시 수치, p50/p95·업무 정답·잘못된 성공·오대상·중복/중단 후 실행·도구 호출/바이트·연결 지표를 수집하고 HTML/Markdown 비교 보고서를 만든다. 미측정은 0으로 보고하지 않는다.
- [ ] 같은 시험·환경으로 수정 전 기준선을 수집한다. 통계/비교/출력 검증 테스트를 먼저 작성한다.
- [ ] 행 재사용 참조, 레이블/root/문맥/disabled, 비동기 입력 원복을 실패 테스트부터 수정한다.
- [ ] 완료 조건을 명시한 조작 대기와 스크롤 검증을 보강하고 고정 관찰/검색의 실제 병목을 줄인다. 실행 뒤 불확실한 쓰기 자동 재시도는 금지한다.
- [ ] 실제 모델 평가에서 목표만 준 업무와 결과 정답을 지원하고 단계/호출/토큰/시간을 수집한다. 기존 Zen 무료/격리 규칙을 유지한다.
- [ ] 수정 후 같은 benchmark로 비교하고 관련 회귀·타입/빌드 및 마일스톤 전체 검증을 수행한다. 실제 Windows 검증을 실행하거나 구체적인 외부 장애를 별도 기록한다.
- [ ] 사용법·검증 결과·남은 경계를 status에 기록하고 과제별 Conventional Commit을 만든다. push/PR/Release는 하지 않는다.

## 구현 원칙

실제 페이지·대화·비밀은 결과 artifact에 넣지 않는다. 테스트 fixture의 실제 상태를 정답으로 삼으며 도구 `ok`와 구별한다. 표본 부족, 환경 차이, 실패/timeout을 숨기지 않는다. 새 의존성이나 자체 에이전트 하네스를 추가하지 않는다. CI는 짧은 합성 수집을 수행하고 긴 비교는 별도 명령으로 실행한다.

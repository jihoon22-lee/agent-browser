# v0.1.9 상세 검토와 브라우저 연속 작업

검토 범위는 브라우저 요청·탭 수명, Windows/WSL 관리 프로세스, GUI·PowerShell 설치/업데이트, 진단 공유, 현재 문서와 배포 내용이다. 실제 조직의 경로·계정·구성 비율·정책 사례는 기재하지 않는다. 현재 검증 결과·릴리스 상태는 [상태 기록](./status.md)을 기준으로 한다.

## 확인한 문제와 처리

| 문제 | 이전 동작 | 변경·확인 방법 |
|---|---|---|
| 기존 여러 탭을 오가는 요청 | operation에 처음부터 포함되지 않은 탭으로 switch 거부 | 소유 Chrome에서 정확한 tabId와 HTTP(S) 여부를 확인한 뒤 명시 선택 |
| 링크·팝업 닫기 후 계속 작업 | 현재 탭이 닫히면 `TAB_CLOSED`에 머묾 | 최근 명시 방문한 살아 있는 탭으로 복귀. 다른 프로필·미방문 탭 제외 |
| 복귀 대상에 이전 지시가 적용될 위험 | 자동 복귀만 추가하면 이전 문맥의 navigate 등이 다른 탭에 적용될 수 있음 | 새 snapshot 전 쓰기·닫기 거부. 늦은 과거 snapshot은 대상 세대로 구분 |
| 기존 탭·빈 탭에서 이동한 페이지 닫기 | 최초 탭 보호와 `window.close` 제한으로 연속 작업 중단 | 현재 선택한 탭을 네이티브 탭 API로 한 번 닫고 onRemoved로 확인. beforeunload 취소 시 보존 |
| 새 탭 요청의 식별자 혼동 | 문맥이 기존 페이지 attach 중심이라 새 탭마다 요청 ID가 필요하다고 오해할 여지 | 첫 attach/new의 requestId와 이후 operationId 사용을 문맥·MCP 설명에 명시. 누락/오류 ID는 계속 거부 |
| WSL 정적 등록 검사 | 실제 Windows 실행이 가능해도 메타데이터가 예상과 다르면 중단 가능 | 해당 배포판·사용자에서 Windows Bridge `--version`을 제한 시간 내 직접 확인 |
| GUI와 스크립트 설치 검사 차이 | PowerShell 경로·상위 폴더 소유자/쓰기 검사와 상태 경계가 약함 | 같은 신뢰 기준 적용. 공유 쓰기·교체 가능 경로·data 이탈·잘못된 설치 ID 회귀 |
| 스크립트 업데이트와 관리 MCP | 구버전 경로를 쓰는 관리 서버 또는 `-NoStart`의 구버전 Bridge가 남음 | 관리 기록이 있으면 사전 거부하고 명시 중지 후 진행. 변경된 이전 Bridge는 중지 |
| 진단 익명화의 경계 | 대소문자가 다른 ID를 합치고 일부 문자열 필드를 그대로 출력 | 대소문자 구분 번호, 코드 허용 목록·버전 형식·정수 종료 코드 검사 |
| 문서와 구현 차이 | 시작 경로, 닫기 제한, 업데이트/진단 부작용 안내가 불일치 | GUI 기본 진입점, 전체 수명주기, WSL의 짧은 실행 검사, 공유 보고서와 원본 진단을 구분 |

브라우저 연결 인증, 다른 Chrome 소유 작업 분리, 요청 중단, 참조의 문서 경계, 쓰기 불확실성, 편집 폼·접근 불가 iframe의 닫기 거부는 유지한다. 전체 보안 인증이나 모든 사이트의 저장 상태 판정을 의미하지 않는다.

## 실제 OpenCode 통합과 모델 경계

`opencode-panel.windows.mjs`는 실제 Chrome 사이드패널, 실제 Windows Bridge, 설치된 OpenCode 1.18.29와 MCP를 연결한다. Windows와 WSL 관리 프로필에서 각각 실행한다. 기존 2개 요청의 현재 탭 읽기와 ID 오류 복구에 더해 `panel-journeys.mjs`의 12개 연속 작업을 수행하며, 완료·공급자 오류 뒤 요청 해제와 Stop 비활성도 확인한다.

이 검사는 합성 provider가 도구 순서를 결정한다. 전송·문맥·API·MCP·페이지 실행은 실제 경로를 지나지만 모델 추론을 검증하는 검사는 아니다. 별도 Zen 무료 모델 요청은 설치본 모델 목록과 공식 무료 가격/가용성을 확인한 뒤 한 번 시도했고 HTTP 403 `FreeTierError`에서 중단했다. 유료 모델 전환·제한 우회·API 키 변경은 하지 않았다.

## 설치·문서 검토 경계

PowerShell 5.1에서 실제 소유 프로세스와 격리 설치 폴더를 사용해 업데이트 거부·명시 중지 후 업데이트·외부 서버 보존·`-NoStart`·rollback·제거를 검증한다. GUI·패키지·WSL 관리 업데이트는 최종 ZIP에서 별도로 확인하고 상태 기록에 결과를 남긴다. 개발용 임시 폴더가 공유 쓰기 ACL을 가진 경우 제품 검사를 완화하지 않고 사용자 전용 테스트 폴더를 사용한다.

현재 문서와 새 배포물에서 환경 식별 사례를 제거했다. 과거 태그·자산·Git 이력은 자동으로 삭제하거나 바꾼 것이 아니다. 모델 추론, 실제 업무 페이지, 접근하지 않은 배포 환경, 모든 Chrome·WSL 버전의 성공은 주장하지 않는다.

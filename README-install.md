# AgentBrowser 설치와 첫 연결

Windows x64용 Chrome 확장과 Browser Bridge를 설치합니다. 관리자 권한이나 Node.js·Rust·Python은 필요하지 않습니다. 기존 OpenCode v1은 별도로 준비되어 있어야 하며, 설치 관리자는 OpenCode·모델·WSL을 내려받거나 기존 설정을 초기화하지 않습니다. 실제 API 계약 기준은 OpenCode **1.18.29**입니다.

처음 설치할 때는 **ZIP 검증 → 설치 → Chrome 확장 로드 → 페어링 → OpenCode 프로필 → 첫 작업** 순서로 진행합니다. 이미 설치했다면 [업데이트](#4-업데이트)부터 확인하세요. 실제 작업은 [사용 안내](docs/user-guide.md), 오류 코드는 [문제 해결](docs/troubleshooting.md)에 있습니다.

## 1. 다운로드 검증과 설치

[공식 Releases](https://github.com/jihoon22-lee/agent-browser/releases)에서 같은 버전의 ZIP과 `SHA256SUMS`를 각각 받습니다. **압축을 풀거나 실행하기 전에** ZIP의 SHA256을 별도로 받은 체크섬의 해당 ZIP 행 또는 GitHub 자산의 SHA256 digest와 비교합니다.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\agent-browser-0.1.9-windows-x64.zip
```

다르면 공식 릴리스에서 다시 받습니다. 현재 exe에는 Authenticode 서명이 없습니다. ZIP 안의 `package-manifest.json`은 파일 누락·변경 확인용이며 다운로드 출처를 증명하지 않습니다.

ZIP 전체를 **설치 대상과 다른 임시 폴더**에 풀고 `AgentBrowser-Setup.exe`를 실행합니다. 기본 .NET Framework를 사용하며 추가 패키지를 설치하지 않습니다.

1. **설치 시작 → 다음**으로 진행합니다.
2. **설치 위치 선택**에서 기본 `%LOCALAPPDATA%\AgentBrowser` 또는 전용 로컬 폴더를 선택합니다.
3. 로그인 자동 시작 여부를 확인하고 **다음 → 설치**를 누릅니다. 기본값은 자동 시작입니다.
4. **Chrome 확장 추가 → Chrome 연결 → OpenCode 설정 → 설정 완료**를 순서대로 진행합니다.

설치 폴더와 상위 폴더의 소유자·교체 권한, 기존 파일 해시를 검사합니다. 다른 일반 사용자가 내용을 바꾸거나 경로를 교체할 수 있으면 중단합니다. 네트워크 경로와 reparse point는 지원하지 않습니다. 기존 폴더의 소유자·권한을 자동으로 바꾸지 않습니다. 새 설치의 제품 데이터에는 현재 사용자·SYSTEM·Administrators만 접근하도록 설정합니다. 경로가 거부되면 **기본 위치로 되돌리기** 또는 허용된 개인 전용 로컬 폴더를 사용합니다. GUI와 PowerShell 모두 같은 경로 신뢰 기준을 적용합니다.

포트·로그인 자동 시작·일반 CLI MCP 등록은 설치 위치 화면의 **고급 설정**에 있습니다. 확장 관리 서버만 사용한다면 기본값으로 진행해도 됩니다. 기존의 다른 설치가 만든 Startup 바로가기는 덮어쓰지 않습니다. 자동 시작을 해제하면 설치 폴더의 `start-bridge.cmd` 또는 마법사의 **기존 설치의 연결 설정**으로 직접 시작할 수 있습니다.

실행 파일이나 로컬 확장 로드가 허용되지 않는 환경에서는 승인된 설치 방법을 확인합니다. 권한·보안 정책을 바꾸는 방법을 설치 해결책으로 사용하지 않습니다.

## 2. Chrome 확장 로드와 페어링

1. 사용할 Windows Chrome 프로필에서 `chrome://extensions`를 엽니다.
2. 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**를 선택합니다.
3. 폴더 선택 창에서 **Alt+D**를 누르고 `%LOCALAPPDATA%\AgentBrowser\extension`을 입력합니다. 다른 곳에 설치했다면 그 폴더 아래 `extension`을 선택합니다. 임시 압축 해제 폴더를 로드하지 않습니다.
4. 마법사의 **Chrome 연결**에서 **토큰 복사**를 누릅니다. 마법사를 다시 열었다면 **기존 설치의 연결 설정 → 다음**으로 진행합니다. Bridge는 이 단계에서 시작됩니다.
5. 확장의 **세부정보 → 확장 프로그램 옵션**을 엽니다. 표시된 Bridge 주소와 복사한 64자리 토큰만 입력하고 **저장 후 연결**을 누릅니다. 기본 주소는 `ws://127.0.0.1:4317/extension`이며 포트를 바꿨다면 설치 결과의 주소를 사용합니다.
6. **Bridge에 연결되었습니다.**를 확인한 뒤 확장 아이콘을 고정하고 눌러 사이드 패널을 엽니다.

페어링은 최초 한 번 필요합니다. 설치 폴더를 유지하는 정상 업데이트는 토큰을 보존합니다. 다른 Chrome 프로필에서는 따로 확장을 로드하고 연결해야 합니다. 토큰·프로필 데이터는 공유하지 않습니다.

## 3. 기존 OpenCode 연결과 첫 작업

마법사의 **OpenCode 설정** 또는 확장 옵션에서 실행 환경을 추가합니다.

| 실행 방식 | 입력할 값 | 시작·중지 주체 |
|---|---|---|
| Windows | 기존 OpenCode exe와 Windows 작업 폴더 | Bridge가 관리 |
| WSL | 배포판 이름, 필요 시 사용자, 해당 Linux 실행 파일·작업 폴더 | Bridge가 해당 프로필만 관리 |
| 외부 서버 | OpenCode v1 주소·인증정보·작업 폴더 | 기존 서버 관리자 |

WSL 경로는 해당 배포판 기준으로 입력합니다. Windows에 설치된 OpenCode를 사용할 때는 Windows 프로필을 선택합니다. Windows 사용자에게 WSL 설치를 요구하지 않습니다. 다른 WSL 작업을 멈추거나 배포판 전체를 재시작할 필요도 없습니다.

탐색은 후보 경로를 표시하며 발견한 exe를 자동으로 실행하지 않습니다. 후보를 선택하고 **확인**하면 버전을 조회합니다. 실행 중인 일반 WSL 배포판의 기본 사용자만 탐색하며 중지된 배포판이나 여러 사용자의 홈을 자동으로 순회하지 않습니다. 후보가 없으면 경로를 직접 입력합니다.

프로필을 저장하고 패널의 **대화 → 실행 설정**에서 선택합니다. 관리 서버는 별도 실행 설정으로 `browser` MCP를 연결합니다. 기존 모델·provider·인증·다른 MCP 설정을 덮어쓰지 않습니다. 전역 OpenCode 설정에 `mcp`가 없다는 것만으로 관리 서버의 연결 실패라고 판단하지 않습니다. 외부 서버는 그 서버의 유효 설정에 MCP를 별도로 등록해야 합니다.

**OpenCode 연결됨**을 확인하고 모델·에이전트를 선택한 뒤 **대화로 돌아가기 → 새 대화 시작**을 누릅니다. 일반 웹페이지에서 다음처럼 요청합니다.

> 현재 페이지의 제목을 읽어줘. 다른 탭으로 바꾸지는 말아줘.

또는 대상 URL을 지정해 새 탭에서 시작할 수 있습니다. Chrome 새 탭 화면에 있어도 새 HTTP(S) 탭 생성은 가능합니다. 모델이 도구를 쓰는지, 선택한 페이지가 맞는지 결과를 확인합니다. API 연결·진단 성공은 실제 모델의 작업 성공을 보장하지 않습니다.

일반 OpenCode CLI에서도 같은 브라우저 도구를 쓰려면 GUI의 **고급 설정 → 일반 CLI에도 browser MCP 등록**에서 실제 Windows/WSL 설정 파일을 추가합니다. 사용자가 수정했거나 다른 설치가 소유한 `mcp.browser`는 덮어쓰지 않습니다. 모델·provider·다른 MCP·JSONC 주석을 보존하며 변경 전 백업을 만듭니다. 여러 설정 파일을 등록한 설치는 GUI로 유지·제거합니다.

## 4. 업데이트

자동 업데이트는 없습니다. 새 릴리스의 변경 기록과 체크섬을 확인한 뒤 다음 순서로 진행합니다.

1. 진행 중인 대화와 브라우저 작업을 마치거나 중단합니다. 웹페이지의 미저장 입력을 저장하고 패널의 미전송 초안도 보관합니다.
2. 새 ZIP을 검증하고 **기존 설치와 다른 폴더**에 전체 압축 해제합니다. 실행 중인 exe나 `extension` 위에 직접 덮어쓰지 않습니다.
3. 새 `AgentBrowser-Setup.exe`에서 **업데이트**와 **기존 설치 폴더**를 선택합니다. 미리보기의 버전·포트·자동 시작·CLI 등록 대상을 확인합니다.
4. **업데이트**를 실행하고 완료 결과를 확인합니다. 실패하면 표시된 원인을 해결한 뒤 **뒤로 → 다음**으로 다시 미리보기합니다.
5. `chrome://extensions`에서 AgentBrowser의 **새로고침**을 누르고 패널을 다시 엽니다. 기존 설치 폴더의 확장을 그대로 사용합니다.
6. Bridge·OpenCode 연결과 선택 모델을 확인하고 간단한 페이지 읽기로 재확인합니다. 문제가 있으면 설치 폴더의 `diagnose.cmd`를 실행합니다.

| 항목 | 정상 업데이트 결과 |
|---|---|
| 설치 ID·페어링·프로필 | 유지 |
| OpenCode 모델·인증·세션·다른 MCP | 유지 |
| 설치 소유 `browser` MCP·실행 경로 | 새 Bridge 경로에 맞게 갱신 |
| Chrome 확장 | 고정 `extension` 경로를 유지, 사용자가 새로고침 |
| 외부 OpenCode 서버 | 종료하거나 다시 시작하지 않음 |

GUI는 Bridge exe 경로나 포트가 바뀌면 유휴 관리 서버를 중지하고 새 MCP 경로로 다시 시작합니다. 작업 중이거나 상태·소유권을 확인할 수 없으면 파일 변경 전에 보류합니다. **설치 후 시작**을 끄면 이전 관리 서버와 Bridge를 중지한 상태로 두고 다음 명시적 시작에 새 경로를 사용합니다. 경로·포트가 같은 재적용은 실행 중 서버를 유지합니다.

충돌이나 중지 확인 실패가 발생하면 설치 상태·runtime 기록을 지우지 않습니다. 새 ZIP의 `diagnose.cmd`는 기존 설치를 교체하지 않고 검사할 수 있습니다. 실행 중인 작업을 마치고, 옵션에서 해당 **서버 중지**가 완료되는지 확인한 다음 재시도합니다. 이전 exe를 수동 삭제하면 기존 MCP 프로세스가 끊길 수 있습니다.

실패 시 설치기는 이번 변경을 되돌립니다. 동시 편집 때문에 복구가 불가능하면 충돌과 복구 위치를 남깁니다. 이 경우 백업이나 상태 파일을 임의로 덮어쓰지 말고 변경 범위를 확인합니다. 이전 ZIP을 덮어쓰는 수동 다운그레이드는 일반 복구 절차로 보장하지 않습니다.

## 5. PowerShell 설치·유지보수

스크립트는 PowerShell 5.1 실행이 허용된 환경을 위한 대안입니다. GUI의 권한 검사를 피하는 경로가 아닙니다. 여러 CLI 설정을 등록했거나 관리 서버의 자동 전환이 필요하면 GUI를 사용합니다.

검증한 ZIP을 푼 폴더에서 Windows PowerShell을 열고 실행합니다. 다음 예시는 기본 사용자 설치 위치를 사용합니다.

```powershell
$agentBrowserInstall = Join-Path $env:LOCALAPPDATA 'AgentBrowser'
.\setup.ps1 -InstallDir $agentBrowserInstall
& (Join-Path $agentBrowserInstall 'show-pairing.ps1')
```

표시된 주소·토큰으로 2절의 Chrome 연결을 진행합니다. 토큰을 출력하므로 터미널 전체를 공유하지 않습니다. 실행 정책 때문에 막히면 GUI 또는 승인된 실행 방법을 사용합니다. 배포된 `.cmd`와 스크립트용 Startup 실행기는 해당 PowerShell 프로세스에만 실행 정책 옵션을 전달하며 영구 정책이나 그룹 정책을 변경하지 않습니다.

| 옵션 | 동작 |
|---|---|
| `-InstallDir <전용 로컬 폴더>` | 설치 대상. 업데이트도 같은 경로 사용 |
| `-NoStartup` | 로그인 바로가기 등록 생략. 소유하지 않은 기존 바로가기는 유지 |
| `-NoStart` | 설치 후 새 Bridge를 시작하지 않음. 경로·포트가 바뀌는 업데이트는 이전 Bridge를 중지 |
| `-Port <포트>` | Bridge 포트. 생략 시 기존 포트 또는 새 설치 기본 4317 |
| `-PackageDir <압축 해제 폴더>` | 스크립트와 다른 원본 패키지를 명시할 때 사용 |

자동 시작을 생략했다면 설치 폴더의 `start-bridge.cmd`로 시작합니다. 처음에 `-NoStartup`을 썼고 계속 수동 시작하려면 업데이트에도 붙입니다.

**스크립트 업데이트 전에는** 작업을 마치고 옵션에서 모든 관리 프로필의 **서버 중지**를 완료합니다. 새 Bridge 경로나 포트로 바뀌는데 관리 런타임 기록이 남아 있으면 파일을 바꾸기 전에 거부합니다. 외부 서버는 그대로 둡니다. 새 ZIP 폴더에서 같은 `-InstallDir`로 `setup.ps1`을 다시 실행하고 확장을 새로고침합니다.

```powershell
.\setup.ps1 -InstallDir $agentBrowserInstall -NoStartup
```

스크립트 제거는 작업을 마친 뒤 실행합니다. 기본은 데이터 보존입니다.

```powershell
& (Join-Path $agentBrowserInstall 'uninstall.ps1') -InstallDir $agentBrowserInstall
```

`-RemoveData`는 해당 설치가 소유한 페어링·프로필 데이터까지 지우는 명시적 선택입니다. 복구용 데이터를 보관할 필요가 있는지 먼저 확인합니다. 기존 OpenCode의 인증·세션·다른 프로그램 데이터는 삭제하지 않습니다.

## 6. 두 번 클릭하는 진단과 제거

**설치 폴더의 `diagnose.cmd`를 두 번 클릭**합니다. 업데이트가 막혔으면 새 ZIP의 `diagnose.cmd`를 실행하고 기존 설치 폴더를 선택합니다. 결과는 창과 `data\diagnostic-report.json`에 표시됩니다.

보고서는 검사 이름·상태·오류 코드·정수 종료 코드·검증된 버전과 익명 프로필 번호만 포함합니다. 토큰·비밀번호·설정 원문·프로필 이름·작업 경로·서버 주소·대화·페이지 원문은 담지 않습니다. 번호는 해당 보고서 안에서만 유효합니다. 문의에는 실패 항목과 오류 코드부터 전달합니다.

진단은 모델 요청이나 브라우저 조작을 하지 않고 관리 OpenCode 서버를 시작·중지하지 않습니다. 다만 프로필의 실행 파일 버전과 WSL 전제 조건을 확인하기 위해 짧은 프로세스를 실행하며, 지정 배포판이 꺼져 있으면 WSL 호출이 배포판을 시작할 수 있습니다. 전체 WSL 종료·재시작이나 설정 변경은 하지 않습니다.

GUI 제거는 마법사의 **제거 → 다음 → 다음 → 제거**로 대상을 확인합니다. 검증된 관리 서버·Bridge·소유 파일·시작 바로가기·소유 MCP만 제거합니다. 페어링·프로필 데이터는 기본 보존되며 GUI에는 데이터 삭제 선택이 없습니다. Chrome 확장은 `chrome://extensions`에서 별도로 제거합니다.
